# Commercial backend setup

**상용 Backend** opens the native tool adapter panel from the design workspace or local file viewer. A standalone viewer performs no RPC or authentication before this explicit action. Hosted standalone pages direct users to the authenticated shared workspace.

1. Review the native catalogue: Virtuoso, Spectre, Assura, Pegasus, Quantus, Custom Compiler, PrimeSim, HSPICE, ICV, StarRC, ICC, ICC2, Fusion Compiler, Calibre DRC/LVS/xACT and Innovus. The ngspice entry is explicitly open-source calibration. Adapter definitions do not prove that a vendor binary, license, site recipe or foundry signoff is available.
2. Select an installed profile and run actual resource validation. Local operators may register a versioned JSON manifest, editing the executable or agent reference, permitted environment **names**, resource paths, recipes, argument placeholders, output roles and constrained parameter schemas. Credentials stay in operator environment/token files. Profile registration is disabled for shared clients; shared owner/editor roles use server-installed profiles.
3. Use the current native project, explicitly upload a local GDS to a separate project, or create a separate netlist project. Choose an implemented operation and existing top cell; provide scalar JSON parameters and bounded input data. The frontend execution input accepts only the 256 KiB data-only classic SPICE subset enforced by the worker. `.control`, `.include`, encrypted models, native Spectre syntax and HDL are unsupported through this input path. Their native files belong in operator-installed trusted resources/site recipes. Draft files can be read/exported without execution; saving unsupported syntax produces a real backend validation error. Proprietary inputs are not silently converted to ngspice. OA/NDM handling requires the installed vendor exporter.
4. Validate and save. Requests include profile hashes, expected revisions and unique command receipts. Setup imports populate inputs without executing. Resaves omit internal server metadata. Dirty input can be reset to persisted values; changed resources require revalidation and invalidate old results.
5. Explicitly run the saved operation. View actual status, independent analysis/freshness, raw logs, normalized waveforms when returned, native artifacts and manifests. Cancellation and artifact downloads use native job APIs. Completed current/scene callbacks are delivered before polling is terminated.
6. A successful layout_export/implementation GDS/OAS artifact can be applied only after explicit confirmation. The run must match the current revision. Original GDS inputs remain archived; exported GDS becomes the active scope source. OAS is displayed through the actual worker scene snapshot, without claiming a browser OAS/OA/NDM parser.

No licensed vendor installation/server was supplied in this session. Actual vendor runs remain unverified.
