# EDA file interchange

Open **EDA 파일 호환** in the workspace or local viewer, then choose **다른 EDA 파일 가져오기**. The source tool preset describes where files came from; file content and the native reader determine supported scope. Opening the panel, choosing files and browser inspection do not perform RPC or authentication.

1. Select companion files together: GDS/OAS geometry, LEF + DEF, a stream map and technology/display data, CDL/SPICE cells and referenced library files, or exported numerical results. Original bytes remain available for download. OA, NDM and Milkyway databases require the owning tool's SDK/exporter; their exported standard files use the file flow here.
2. Review each file. Browser data parsers read narrow Cadence ASCII techfile/DRF/LPP stream-map and Synopsys brace-data technology metadata, cds.lib/lib.defs references and CDL/SPICE cell/port/device tokens. Partial and unsupported statements are retained. Library paths and include statements are metadata, with no environment expansion or code execution. Technology internal numbers remain distinct from GDS layer/datatype.
3. Choose the explicit stream-map and DRF companions. Apply the normalized PDK display layers to the current GDS, or export a layer JSON and compatibility bundle retaining original sources, diagnostics and unsupported nodes. Colors come from actual matched display packets; heights without supplied physical data remain illustrative.
4. Edit CDL/SPICE text as a working copy when needed, and press **수정본 로컬 구조 검사**. The original bytes are preserved separately. This is circuit data editing; it does not invent a schematic or silently select SKY130 models. Native safe imports resolve only uploaded, confined library closure and retain pin order/model names.
5. In **프로젝트 적용 / 내보내기**, choose layout/netlist top cells and uploaded netlist/library scope. Use the selected file's explicit stream-map rows, adjusting named layer/purpose/GDS values when needed. Native inspection uses actual KLayout and document parsers. Unmapped layers fail closed by default; any permitted limited display has a loss report. Press **프로젝트에 명시적 적용** to commit a new revision. Local standalone imports create a separate project; shared imports require editor/owner rights.
6. Export actual GDS/OAS or preserved CDL/SPICE files and inspect the roundtrip/loss report. This flow has no LEF/DEF writer claim. Reimporting the resulting GDS/OAS uses the same standard reader. A standalone DEF/OAS native scene is a bounded snapshot; its portable viewer file retains the displayed scene, while original LEF/DEF files remain separately downloadable from the interchange panel.
7. Import externally exported results with an explicit file role/parser. CSV controls select real header columns, analysis, X unit, signal unit and current from/to nets. Declared engineering units are normalized to SI without changing sign or zero samples. A local CSV preview works without a worker; native result import persists **imported-results** history. Both state that engine/vendor execution is unverified. Current paths remain unmapped until separately declared by the user, with physical GDS correspondence unverified.

The advanced **상용 Backend** panel remains separate for operator-installed execution. Direct file compatibility does not require an operator recipe JSON. Imported PEX summaries do not activate native post-layout simulation or fabricate spatial extraction mappings. Actual extraction/simulation of imported geometry uses **PDK·해석 설정** with registered, validated model/technology resources and explicit biases.

Focused browser evidence is written to `packages/ui/qa/interchange-ui.json`. Metadata grammar fixtures are labeled synthetic; the public SKY130 GDS and actual native LEF/DEF import/export checks are separate from licensed vendor execution.
