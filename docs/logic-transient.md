# 동적 신호·지연 검증

Resistor Edu와 Resistor Industry는 같은 회로 IR, ngspice 실행 경로와 수치 분석 모듈을 사용합니다. 이 기능은 직접 조합한 회로의 실제 전압 파형에서 단일 입력 경로의 논리 관계·지연을 확인합니다. 학습 체크박스와 엔진 실행 결과를 혼합하지 않습니다.

## 실습: AND → INV의 전이 관찰

사전 지식: 전원과 ground, CMOS 반전, 커패시터 부하, ns/ps 단위. 목표: 입력과 출력의 전이가 즉시 일어나지 않는 이유를 실제 표본과 회로로 설명하기.

1. **회로도 / Schematic → 기본 로직 → AND → INV → 새 조합 실습**을 누릅니다. 기존 프로젝트는 그대로 남습니다.
2. **동적 신호·지연 검증 · PULSE / PWL**을 펼치고 **클록 실험 설정**을 누릅니다. A만 펄스이며, B=VDD입니다. 반가산기는 B=0, MUX 조합은 B=VDD·SEL=VDD입니다. 이렇게 다른 제어 입력을 고정해야 선택한 경로의 반전/동상 관계를 관찰할 수 있습니다.
3. 실제 소스 `VIN_A`를 확인합니다. 기본값은 0→VDD, 시작 2 ns, 상승/하강 100 ps, High 평탄부 4.9 ns, 주기 10 ns입니다. 공급 전압은 원래 VDD의 명시적 DC 값을 사용합니다. 자동 전원 추정은 없습니다.
4. **실제 Transient 실행**을 누릅니다. 40 ns 동안 최대 시간 간격 5 ps로 ngspice를 실행하고 Simulation 화면으로 이동합니다. 엔진·모델이 없으면 설치/모델 오류를 표시하며 예시 파형으로 대신하지 않습니다.
5. **동적 신호·지연 검증**에서 입력/출력, tpLH·tpHL 평균, 10–90% 상승·90–10% 하강 시간, 주기별 표본 교차 구간을 확인합니다. 평균 외에 모든 관찰 전이가 기준을 만족해야 합니다.
6. 부하 `CLOAD_Y`를 5 fF에서 50 fF로 바꾸고 다시 실행합니다. 실제 측정값과 이전 revision을 비교합니다. 이 QA 조건에서는 1 ns 상승 시간 한도를 넘었습니다. 한도를 바꾸면 다른 명세의 실험이므로 변경 사실과 기준을 함께 기록하세요.
7. **저장 → 열기**로 다시 엽니다. 결과에는 실행 당시 소스·기준·revision이 남습니다. **타이밍 JSON**은 원본 실행 ID, 조건, 판정 근거와 표본 구간을 내보냅니다. 설계가 바뀌면 이전 실행은 현재 합격 판정으로 재사용하지 않습니다.

해석 질문: 부하를 늘렸을 때 tpLH와 tpHL이 같은 비율로 변합니까? 입력 상승 시간과 출력 상승 시간은 같은 값입니까? 시간 간격을 절반으로 바꿔도 같은 결론입니까? 한도와 관측 평균이 가까우면 무엇을 추가 확인해야 합니까?

## 직접 설정하는 입력

전압원·전류원의 DC, PULSE, 비반복 PWL을 지원합니다. DC는 OP 바이어스이고 transient에는 저장한 자극이 적용됩니다. 정적 0/1 버튼은 해당 소스를 명시적으로 DC로 되돌립니다. 전류원 레벨은 A, 전압원은 V입니다. 시간 입력은 ns/ps, 저장·API는 SI seconds입니다.

PWL은 한 줄에 `시간(ns) 값(V 또는 A)` 두 수치를 입력합니다. 0 ns부터 시작하고 시간은 엄격하게 증가해야 하며 마지막 값을 유지합니다. 반복을 임의로 추가하지 않습니다. 예를 들어 두 번의 전이를 넣으려면:

```text
0 0
2 0
2.1 1.8
7 1.8
7.1 0
12 0
12.1 1.8
17 1.8
17.1 0
40 0
```

빈 값, 비수치, 0인 전이 시간, 중복 PWL 시간, rise+width+fall보다 짧은 주기, 임의 SPICE 표현식은 거절합니다. 최대 시간 간격은 가장 짧은 소스 전이의 1/5 이하여야 합니다. 지원 한도는 1 ps–1 ms, PWL 2–2048점, 실행당 최대 1024 펄스 주기, nominal 전압 trace 200만 표본입니다. 이는 수치 자원 한도이며 소자 모델의 유효 동작 범위를 보증하지 않습니다.

## 판정의 의미와 한계

- **기준 충족**: 실제 완료한 ngspice transient의 모든 관찰 전이·정착 논리 레벨이 저장된 단일 경로 기준을 만족합니다. 기본 정착 후 low≤30%, high≥70%입니다.
- **기준 불충족**: 지연·전이 시간이 한도를 넘거나, 해당 입력 구간의 출력 교차 누락·추가 교차·기대 논리 레벨 불일치가 관측됐습니다.
- **판정 불가**: 필요한 주기, 완전한 10–90% 전이, 시간 범위 또는 파형이 부족합니다. 한도가 교차 표본 구간 안에 있으면 점 추정값만으로 통과시키지 않고 더 작은 시간 간격을 요구합니다.
- **이전 조건**: 설계 revision 또는 엔진/모델 출처가 달라진 기록입니다. 수치는 보존되지만 현재 결과로 승인하지 않습니다.

지연은 해당 입력의 50% 교차부터 출력의 50% 교차까지입니다. 입력 10% 전이 시작부터 다음 입력 전이 시작까지 같은 구간에서만 짝을 찾습니다. 느린 입력에서는 출력 50%가 먼저 도달해 음의 지연이 나올 수도 있습니다. 추가 50% 교차는 글리치로 구분합니다. 더 짧고 표본 사이에 숨은 글리치가 없다고 증명하지는 않습니다. 반복 입력에서도 이후 주기의 출력을 빌려 누락을 숨기지 않습니다.

원본 비균일 시간 좌표에서 선형 보간하며 표시용 파형 축소본은 사용하지 않습니다. `tran TSTEP TSTOP 0 TMAX`에 TMAX를 명시합니다. 한도 근처에서는 더 작은 TMAX와 모델·부하 조건을 바꿔 수렴을 확인하세요. PULSE의 width는 high 평탄부이며 주기에는 상승·하강 시간이 포함됩니다. 형식은 [설치 버전과 같은 ngspice 42 공식 매뉴얼](https://ngspice.sourceforge.io/docs/ngspice-42-manual.pdf)을 따릅니다.

이 결과는 전체 진리표, 모든 경로, 동시 다중 입력, setup/hold, STA, PVT sweep 또는 제조용 타이밍 보증이 아닙니다. 수치 엔진의 `analysis_result=unknown`을 유지하고 조건별 타이밍 판정을 별도 표시합니다. DRC/LVS/PEX는 독립 실행이며 이 조합 흐름은 레이아웃을 자동 생성하지 않습니다.

## 저장·호환성과 QA

기존 schema 1 프로젝트의 `stimulus` 누락은 기존 DC 동작과 바이트 호환 netlist를 유지합니다. `Device.stimulus`, root `timing_check`, Run의 `timing_recipe`·`source_stimuli`는 선택적 필드입니다. 변경 후 새 revision을 만들며 과거 실행 파일은 수정하지 않습니다. 하위 계층은 해석 사본에서만 펼치고 전역 ground 및 자극을 보존합니다. 회로→레이아웃 변환의 외부 소스 기록에도 자극을 보존합니다.

공통 소스는 `main`에서 edition 브랜치로 전달하며 프로젝트·저장 공간·edition 설정은 구분합니다. 실행 방법은 `npm run dev:edu`, `npm run dev:indust`입니다. 도구를 준비한 뒤 `npm run test:logic:transient`를 실행하며 Windows는 `-- --wsl=ResistorEDA`처럼 설치한 실제 배포판을 선택할 수 있습니다. QA 전용 workspace는 기본 `.runtime/logic-qa/workspace`, 포트 18985이며 사용자 프로젝트와 키를 복사하지 않습니다.

[수치 실행 증거](evidence/logic-transient/native.json)는 3개 CMOS 조합, PULSE/PWL, 1 ps 지연 한도 불충족, 50 fF의 1 ns 상승 한도 불충족, 명시적 1.5 ns 기준 변경, 시간 간격 절반 수렴, 부족한 주기, stale·저장/재열기와 RC 해석식을 확인합니다. RC R=1 kΩ·C=1 pF에서 첫 상승의 유한 ramp 보정 지연과 10–90% 시간 τ ln 9를 10 ps 허용 범위로 비교합니다. 학습 효과 평가나 제조 signoff 증거는 아닙니다.
