# 인터넷 업데이트

Resistor v0.23.0부터 설치 앱의 **업데이트** 버튼으로 새 버전을 확인하고, 공식 파일을 다운로드·검증한 뒤 설치할 수 있습니다. 이전 버전에는 이 기능이 없으므로 [다운로드 사이트](https://resistor-downloads.vercel.app/)에서 v0.23.0을 한 번 설치해야 합니다.

1. 앱을 시작하거나 인터넷에 다시 연결하면 버전을 확인합니다. 앱이 열린 동안에는 6시간 간격으로 확인하며, 자동 확인은 설정에서 끌 수 있습니다. 재연결 확인에는 15분 제한을 둡니다.
2. **지금 확인**으로 즉시 확인할 수도 있습니다. 현재 배포는 미리보기이므로 기본적으로 미리보기 릴리스를 포함하며, 정식 릴리스만 받도록 변경할 수 있습니다.
3. 새 버전의 변경 내용·파일 크기·SHA-256을 확인하고 **업데이트 다운로드**를 누릅니다. 실제 받은 바이트로 진행률을 표시합니다. 중단·취소 후 다시 다운로드할 수 있으며, 검증 완료 파일은 앱을 다시 열어도 재사용합니다. 부분 다운로드 재개는 지원하지 않습니다.
4. 설정 초안과 브라우저 로컬 뷰어 파일을 저장하고 **설치하고 다시 시작**을 누릅니다. 설치 확인창에서 승인한 뒤 적용합니다.

## 운영체제별 설치

| 환경 | 적용 방식 |
| --- | --- |
| Windows x64 | 검증된 NSIS 설치 안내를 열고 앱을 종료합니다. 안내에 따라 같은 설치 폴더를 선택하고 완료 후 실행을 선택합니다. 설치 프로그램을 취소하면 기존 앱을 다시 여세요. |
| Mac arm64 / Intel | 압축·번들 식별자·버전·아키텍처·자체 서명을 검사한 후 사용자 `Applications/Resistor.app`에 설치합니다. 기존 앱을 백업하고 부모 앱이 종료된 뒤 교체·재실행합니다. |
| Linux x64 | 실제 ELF 아키텍처·버전을 검사하고 사용자 `.local/opt/resistor/<version>`에 설치합니다. 애플리케이션 메뉴의 실행 경로를 갱신하고 재실행합니다. |
| 브라우저 / 소스 실행 | 버전 확인과 공식 다운로드를 제공합니다. 소스 실행 중에는 설치 앱 교체를 차단합니다. |

Mac·Linux의 교체 또는 실행 요청이 실패하면 기존 대상 앱을 복원하고 실패한 새 앱도 별도로 보관합니다. 설치 영수증과 캐시는 기존 사용자 데이터 폴더의 `updates`에 기록합니다. 새 앱은 영수증의 버전과 실제 실행 버전을 비교해 완료 여부를 표시합니다. 실행 요청 성공과 화면의 정상 동작 검증은 별개입니다. Windows의 OS 설치 안내·취소·복구는 NSIS가 관리하며 이 기능이 별도의 Windows 앱 백업을 보장하지 않습니다.

## 데이터와 엔진

기존 한국어 사용자 데이터 경로와 작업 폴더를 유지합니다. 업데이트 파일은 별도 캐시에 저장하며 프로젝트·PDK·키·작업자 설정을 업로드하거나 덮어쓰지 않습니다. 다운로드에 인증 키는 필요하지 않습니다.

Docker 엔진은 앱과 별도로 관리합니다. 업데이트가 실행 중인 엔진이나 해석 작업을 강제 종료·교체하지 않습니다. 앱 업데이트만으로 엔진이 최신이라고 표시하지 않습니다. 엔진을 갱신해야 할 때는 기존 [설치·연결 안내](desktop-installation.md)를 따르세요.

## 신뢰와 릴리스 절차

업데이트 정보는 고정된 공개 GitHub 저장소 `Lead729726-cell/Resistor`의 Releases API에서 받습니다. 드래프트·동일 버전·낮은 버전과 다른 아키텍처는 설치하지 않습니다. 파일명·릴리스 주소·크기와 실제 GitHub 자산의 SHA-256을 확인합니다. 다운로드 리디렉션도 GitHub와 해당 릴리스 자산 호스트로 제한합니다. 해시가 없거나 일치하지 않는 파일은 설치하지 않습니다. 임의 URL·파일 경로·명령을 렌더러에서 전달할 수 없습니다.

TLS와 GitHub 배포 메타데이터를 신뢰하는 구조입니다. GitHub 계정 탈취까지 방어하는 별도 서명 피드는 아니며, Apple Developer ID·공증이나 Windows Authenticode를 대신하지 않습니다. 해당 서명은 아직 없으며 OS 보안 정책에 따라 확인이 필요할 수 있습니다. 시스템 보안 설정을 변경하지 않습니다.

새 릴리스에는 더 높은 `vX.Y.Z` 태그를 사용하고, 운영체제별 파일 업로드가 끝난 뒤 공개해야 합니다. Mac 파일의 `rN`만 바꾸고 같은 버전을 다시 배포하면 업데이트 대상으로 취급하지 않습니다. 다운로더는 아직 파일이 없는 아키텍처에 다른 운영체제 파일을 제공하지 않습니다.

내장 Electron 자동 업데이트는 현재 NSIS·Linux tar.gz·자체 서명 Mac 배포 방식 전체를 지원하지 않아, 기존 설치 형식을 유지하는 명시적 다운로드·설치 절차를 사용합니다. [Electron 공식 자동 업데이트 문서](https://www.electronjs.org/docs/latest/api/auto-updater).

검사: `node --test --test-isolation=none tests/desktop-updates.test.mjs`. 네이티브 압축 설치 검사는 `node scripts/update-native-qa.mjs <archive>`로 해당 OS에서 실행합니다. 실제 배포·네이티브 검사 결과는 검사가 완료된 뒤 별도 증거로 기록하며 미실행 결과를 통과로 표시하지 않습니다.
