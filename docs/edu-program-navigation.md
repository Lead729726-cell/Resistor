# Resistor Edu 메인과 7단계 설계 화면

실행: `npm run dev:edu`. 첫 화면에서 **퀴즈·자율학습** 또는
**설계·시뮬레이션 학습**을 고른다. 선택 전에는 새 프로젝트를 자동 생성하거나
문제 은행·리그·EDA 작업대를 미리 구동하지 않는다. 상단 메인으로 언제든 돌아간다.

메인의 **이어서 학습**은 이 기기의 마지막 화면 위치로 이동한다. 퀴즈 탭도 주소와
뒤로가기에 연결된다. [초안 충돌·복원과 확인 기록](edu-continuation-review.md)을 참고한다.
상단 **학습 프로젝트**에서 실습별 조건·실행·초안을 보고 다시 열 수 있다.
[연결 재시도와 프로젝트 대시보드](edu-dashboard.md)에 사용법과 검증 범위를 정리했다.

## 프로그램 안의 오늘의 리그

메인의 **오늘의 리그 · 프로그램에서 참여**를 누르면 외부 브라우저 대신 앱 내부의
리그·순위·커뮤니티를 연다. 공개 GitHub Pages의 `league-config.json`에서 최신 공용
HTTPS 서버 주소와 고정 identity namespace를 확인한다. 설정은 Edu schema로 검증한다.
새 터널 주소가 배포되면 **공용 서버 주소 새로고침**으로 확인한다.

기기 등록·참가·제출은 기존 서명된 요청과 서버 채점을 그대로 사용한다.
개인 회로·실습 기록·API 키를 리그 서버에 보내지 않는다. 공식 서버와 내 서버 연결을
구분하며 연결 오류를 로컬 리그로 임의 전환하지 않는다. 운영 PC·터널이 꺼져 있으면
해당 연결 오류를 표시한다. 웹과 설치 앱은 저장 origin이 다르므로 같은 물리 기기라도
각 환경의 기기 키·등록은 별도다.

## 한 번에 한 페이지

첫 연결 설계 과정은 기존 지원 예제인 CMOS 인버터다. 새 아날로그 전체 레이아웃이나
제조 signoff를 생성하는 흐름이 아니다.

1. 실습 시작: 기존 설계를 보존하는 새 프로젝트 또는 저장된 실습 선택.
2. 연결 관찰: 소자·핀·넷을 읽고 실제 회로도·레이아웃 편집 화면 열기.
3. 적층 확인: layer mapping·표시 Z·실제 공정 입력의 차이와 단면/3D 확인.
4. 기준 해석: 변경 전 실제 실행 상태·파형·독립 검증 범위 확인.
5. 조건 변경: 하나의 출력 부하 입력과 적용. 현재 실제 조건과 입력 초안을 구분.
6. 재해석·비교: 실제 run ID·revision·조건·지연 비교.
7. 설명·저장: 학생의 설명과 학습 기록 저장·재열기.

전체 화면에서 현재 단계의 옵션만 렌더링한다. 이전·다음은 하단에 유지하고,
`#design/1`–`#design/7` 경로로 뒤로가기와 새로고침을 지원한다. 실제 작업대에서
**설계 학습 N/7로 돌아가기**를 누르면 같은 단계로 돌아온다. 학습 페이지와 과거
revision의 실제 결과는 구분하며 페이지를 넘겨도 PASS를 만들지 않는다.

## 확인

- 실제 앱에서 메인 → 리그의 공용 서버 `연결됨` 확인. 공개 리그 참가·제출·글 게시를
  QA로 생성하지 않았다. 해당 동작의 채점·서명·중복 방지는 기존 서버 테스트를 재사용한다.
- 기존 QA 실습에서 1–7 이동·단일 페이지·최종 다음 비활성·브라우저 뒤로가기,
  회로도 열기·복귀, 입력 95 fF 초안의 이전·다음·새로고침 복원을 확인했다.
- 390px 화면에서 가로 넘침 없이 옵션과 하단 이전·다음을 확인했다.
  업데이트 버튼은 상단에 두어 다음 버튼과 겹치지 않는다.
- 기존 QA의 실제 5/75 fF 결과는 보존했다. 이번 화면 검사에서 새 전기적 결과나
  학생 제출·학습 효과 평가를 생성하지 않았다.
