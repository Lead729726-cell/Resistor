# Resistor Edu 개인정보 수동 처리 운영 절차

2026-11-12 · 운영 책임자: 대표 이석형 · 담당 연락처: creditlsh00726@gmail.com.
**승인된 운영 기준과 필요한 실행 절차를 문서화한 것이다. 실제 요청 처리·삭제 완료 기록이 아니다.**
국외 이전, 아동 처리 범위, 인증·발송·협업의 세부 기간, 백업 파기 검증과 전체 정책 시행일은 미확정이다.

## 승인한 기준

| 분류 | 보관 기준 | 운영 처리 |
| --- | --- | --- |
| 일반 문의 | 해결 후 1년 | 해결일을 남기고 기한 도래 시 법정 보존 대상인지 검토한 뒤 수동 파기 |
| 리그·커뮤니티 | 이용 중 보관 | 본인과 범위를 확인한 삭제·탈퇴 요청을 수동 처리 |
| 해당 거래·분쟁 기록 | 별도 법정 기간 | 일반 문의·서비스 데이터와 구분하여 제한된 목적으로 보존 |

해당 법정 기록은 표시·광고 6개월, 계약·청약철회 및 대금결제·공급 5년,
소비자 불만·분쟁 3년이다. 실제 보유 기록과 적용 근거를 확인하며 모든 문의를 3년 또는
5년 보관 대상으로 확대하지 않는다. 기산점과 보존 근거가 불명확하면 임의 삭제·연장을
하지 않고 책임자가 확인한다. [전자상거래법 시행령 제6조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lspttninfSeq=63460).

## 접수부터 완료까지

1. **접수**: 기능, 요청 종류(열람·정정·삭제·처리정지·탈퇴), 대상 범위를 확인한다.
   내부 사례 ID만 발급하고 일반 로그·GitHub·공개 증거에 이메일, 본문, 시리얼, 키를 남기지 않는다.
   대장에는 접수일, 담당자, 요청 범위, 최소 대상 참조, 상태와 다음 확인을 기록한다.
2. **본인·관리 주체 확인**: 이메일 계정이나 해당 기기·서버에 연결된 기존 인증 수단을 이용한다.
   닉네임, 주문번호 일부 또는 새로 보낸 이메일만으로 다른 사람의 데이터를 삭제하지 않는다.
   비밀번호, 개인키, 전체 시리얼, API 키, 신분증을 기본 제출물로 요구하지 않는다.
   기기 키를 잃었다면 확인 불가 상태로 남기고 책임자가 별도 최소 증명 방법을 검토한다.
3. **읽기 전용 조사**: 어느 서버·edition·DB인지 확인하고 정확한 대상 ID에 연결된 건수와
   관계만 조사한다. Edu 요청으로 Industry 데이터나 다른 리그·자체 운영 서버를 수정하지 않는다.
   사용자 기기의 로컬 파일과 외부 수신자가 가진 사본은 원격 삭제 가능 범위로 표시하지 않는다.
4. **보존·영향 분리**: 일반 파기 대상, 법정 보존 대상, 다른 참여자와 공유한 기록, 외부 제공자
   보관분, 백업을 분리한다. 이유·기준·대상 범위를 알리고 요청 범위를 넘는 데이터는 보류한다.
   환불·사용권 회수·기기 해제·글 숨김을 개인정보 삭제와 혼동하지 않는다.
5. **실행 계획 검토**: 대상 ID와 실행 전 버전/해시, 예상 변경 건수, 관계 영향, 보존 예외,
   복구 또는 중단 조건을 검토한다. 정확한 작업 계획을 승인받은 뒤 담당자가 실행한다.
   현재 검증된 전용 삭제 도구가 없는 DB 작업은 먼저 복제한 합성 테스트 데이터에서 구현·검증한다.
6. **실행·검증**: 실행 도중 충돌·건수 불일치·예외가 있으면 중단하고 실패 또는 부분 처리로 남긴다.
   재조회로 실제 제거·보존 건수와 공개 화면·접속 상태를 확인한다. 제3자 기록이 유지되는지 확인한다.
   삭제된 내용이 백업 복원으로 되살아나지 않도록 복원 전 재적용 목록과 절차를 검토한다.
7. **결과 안내**: 완료한 범위와 일시, 별도 보존 대상·근거, 미완료 사유·다음 처리를 구분한다.
   메일 발송 접수, 글 숨김 또는 DB 명령 성공만으로 전체 삭제 완료를 선언하지 않는다.
   최소 처리 대장과 보존 예외의 기간도 별도로 검토하며 새 무기한 보관 정책을 만들지 않는다.

단계 상태는 `received → identity_verified → planned → approved → executing → verified`로
구분한다. `awaiting_verification`, `blocked`, `partial`, `failed`는 완료가 아니다.
개인정보 권리행사의 적용 법정 기한은 요청 종류·예외에 맞춰 확인하고, 이 문서에서 임의의
일괄 처리기한이나 무조건적인 즉시 삭제를 약속하지 않는다.

운영자 계정의 Gmail 메일 수동 삭제에도 실제 사용자 요청과 대상 확인이 필요하다.
이 문서 작성 자체는 메일 열람·삭제, DB 조회·변경, 사용자 연락 또는 라이선스 회수를 실행하는 지시가 아니다.

## 수동 지원 도구의 최소 안전 계약 — 아직 미구현

현재 공개 API에 임의 SQL 실행·일괄 삭제 경로를 추가하지 않는다. 지원 도구를 개발할 때는 다음을 충족해야 한다.

- 기본 모드는 **읽기 전용 계획**. 입력은 확인한 사례 ID, 정확한 서버/edition/authority,
  대상 내부 ID, 요청 유형, 보존 예외이다. 이메일·키·시리얼을 CLI 인자나 로그에 넣지 않는다.
- 출력에는 대상별 건수, 관계 영향, 보존 예외, 현재 revision/hash, 계획 해시를 담는다.
  원문 답안·암호화 해제 데이터·개인키를 불필요하게 출력하지 않는다. 계획은 비공개 경로에 최소 권한으로 저장한다.
- 적용은 별도 명시 작업이며 승인한 **동일 계획 해시**와 실행 시점 상태를 대조한다.
  대상이 모호하거나 요청자가 확인되지 않았거나 DB/환경·건수가 달라지면 실패해야 한다.
- 거래·환불·메일 발송 중 작업은 재시도·중복 방지 상태를 보존한다. 라이선스 발급/환불을
  삭제 요청의 대용으로 실행하지 않는다. DB 트랜잭션, 외래키·참조 무결성, 동일 사례의 재실행 안전성을 검증한다.
- 리그 닉네임에는 삭제된 ID를 다시 연결하지 않는다. 다른 이용자의 답글·신고는 별도 권리·보존
  근거를 확인하며 다른 이용자의 데이터까지 연쇄 삭제하는 기본값을 두지 않는다.
- 일반 문의의 기한 계획은 유효한 해결일을 가진 기록만 대상으로 한다. 미해결·날짜 불명·법정
  보존 기록은 별도 검토한다. 고객에게 안내하지 않은 새 수집·보존 기간을 도구 기본값으로 만들지 않는다.
- 합성 데이터로 다른 이용자 보존, 잘못된 ID/edition 거부, 날짜 경계, 보존 예외, 중간 실패·롤백,
  상태 변경·동시 요청, 재실행, 백업 복원 후 재적용을 검증한다. 운영 데이터는 테스트 재료로 복사하지 않는다.
- 완료 증거에는 사례 ID·시각·범위별 실제 건수·미완료 사유를 최소한으로 남긴다.
  실제 제거가 확인되기 전 `verified`로 기록하지 않는다. 자동 스케줄러는 현재 범위에 포함하지 않는다.

공개 안내와 소스 검사에서는 승인된 보관 기준을 표현할 수 있지만, 도구 구현·실제 절차 검증과
나머지 정책 확인이 끝나기 전 전체 개인정보 처리방침을 확정 완료로 표시하지 않는다.
