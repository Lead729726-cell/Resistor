# Resistor Edu · 회로 퍼즐과 대화 코치

앱에서 **교육 실습 → AI 자율학습 → 회로 퍼즐·대화 코치**를 연다. 기존 문제 은행 64개는 옆의 **문제 은행·AI 자율학습**에 보존되어 있다. `npm run dev:edu`로 개발 앱을 실행한다. 기존 Edu 저장 공간을 유지하며 Industry 데이터나 키를 복사하지 않는다.

## 직접 해보기

1. 미션과 기록 용도를 고르고 **새 퍼즐 시작**을 누른다. 자동 검증에는 ‘기능 QA’를 사용한다.
2. 트레이의 저항을 누른 뒤 회로 자리를 누르거나, 마우스·손가락으로 끌어 놓는다. 기존 부품도 다른 자리로 이동할 수 있다. Tab·Enter로 부품 선택과 배치가 가능하다. Esc는 선택·이동을 취소한다.
3. 자리 이름보다 노드 연결을 읽는다. 첫 문제는 R1 = VCC→OUT, R2 = OUT→GND이다. X1은 OPEN으로 끝나는 열린 가지다. X1의 부품이 필수 경로를 대신한다고 계산하지 않는다.
4. 수치·공식·전력 정격을 보고 **회로 확인하기**를 누른다. 목표 오차 ±1%와 전력 정격·전류 상한 조건을 각각 검사한다. 이 결과는 **퍼즐 조건 충족**이지 엔진 PASS가 아니다.
5. **단계별 힌트**, 빠른 질문 또는 자유 질문으로 코치와 대화한다. 기본 모드는 저장된 규칙에 따라 응답하는 무료 코치다. 생성형 AI를 실행한 것처럼 표시하지 않는다.
6. 한 저항을 바꾸고 결과를 비교한다. 이전 확인과 대화에는 원래 보드 revision을 남기며, 배치를 바꿨으면 ‘이전 배치’ 또는 ‘현재 배치 미확인’으로 표시한다. 되돌리기·다시 배치를 지원한다.
7. 변화의 이유를 직접 쓰고 **내 설명 저장**을 누른다. 배치·확인·대화는 동작마다 저장한다. 저장 목록에서 다시 열거나 **퍼즐·대화 내보내기**로 JSON을 보관한다.

## 미션 10개

| 미션 | 관찰할 개념 |
|---|---|
| 전압을 절반으로 | 같은 값의 저항 두 개와 2.5 V 출력 |
| 저항의 자리를 찾아라 | 위·아래 저항 비와 1/3 출력 |
| 뒤바뀐 분배기 수리 | 같은 부품을 다른 노드 사이로 이동 |
| 전류를 제한해라 | 직렬 저항 합과 2.5 mA |
| 병렬 길 찾기 | 병렬 연결, 500 Ω 등가 저항 |
| LED 앞에 저항 꽂기 | 일정 Vf 가정의 3 mA 전류 제한 |
| 값이 같아도 뜨거워진다 | 전압 목표·전류 상한·각 저항의 정격 |
| 작은 저항의 함정 | 전류는 맞지만 정격이 부족한 경우 |
| 커패시터 충·방전 | R/C 핀 연결과 실제 전압·단자 전류, C 변경 비교 |
| 트랜지스터로 전하 빼기 | 공개 NMOS D/G/S/B, 게이트 대조 연결과 부하 변경 |

해법은 부품 ID 정답표가 아니라 공통 계산기의 수치와 선언된 연결·정격 조건으로 결정한다. 따라서 조건을 만족하는 다른 조합도 인정한다. 동일 실물 부품 ID를 두 자리에 복제할 수 없다.

## AI 설명과 토큰 재사용

코치 모드에서 **AI에게 현재 회로 물어보기**를 선택하면 기존 승인된 키 참조·공통 누적 예산과 학습 예산을 사용한다. 새 호출에는 질문·배치의 전송 승인과 남은 비용 상한이 필요하다. 기존 [AI 자율학습 비용 설정](edu-self-study.md)을 재사용하며 자동 호출·자동 재시도는 없다.

동일한 미션 버전, 정렬된 부품 배치, 수식 결과, 정규화한 질문, 모델·코치 프롬프트 버전의 응답은 저장해 재사용한다. 배치 순서가 다르거나 되돌린 경우라도 실제 조건이 같으면 캐시를 쓴다. 같은 요청 ID는 동작이나 유료 호출을 반복하지 않는다. 재전달 시 원래 요청 버전과 현재 저장 상태를 구분한다. 이전 대화 전체는 모델에 전송하지 않고 현재 미션·배치·질문만 보낸다고 화면에 명시한다. 생성형 AI의 설명이 연결 검사나 수치 판정을 바꾸지는 못한다.

실패한 AI 질문도 저장하며 완료한 답변처럼 표시하지 않는다. 비용 예약은 보수적으로 유지한다. API 키는 응답·대화·내보내기에 포함되지 않는다. 실제 모델 품질과 교육 효과는 별도 평가 대상이다.

## 구현과 저장 경계

- `packages/education/src/circuit-puzzles.ts`: 선언된 가상 회로, 배치 불변식, 공통 수식 평가, 무료 규칙 코치.
- `scripts/interactive-study.mjs`: 세션·버전·되돌리기·캐시·예산 처리. 기존 `study.*` 잠금·원자적 저장과 OpenAI 요청 helper를 공유한다.
- `packages/ui/src/CircuitPuzzleLab.tsx`: SVG 회로판, 포인터 캡처 방식의 마우스·터치 드래그, 키보드·클릭 배치, 대화 기록.
- 기존 Edu `.runtime/education/study/state.json` 스키마 1에 `puzzle_sessions`, `puzzle_tutor_cache`를 선택 필드로 추가한다. 기존 문제·답안·채점 캐시를 이동하거나 덮어쓰지 않는다. 전체 학습 내보내기에도 퍼즐 기록을 포함한다. 버전이 다른 퍼즐은 재계산하지 않고 전체 원본 내보내기로 보존할 수 있다.
- Edu MCP: `register_study_puzzles`, `register_study_puzzle_create/open/act/tutor`. Industry에서는 저장·모델 호출 전에 거부한다. 정적 퍼즐은 프로젝트 ID null·공정 미지정·정적 계산 엔진을 표시한다. 동적 퍼즐은 실제 프로젝트·실행·모델·공정과 보드 revision을 함께 보존한다. `register_study_puzzle_simulate/refresh`는 실제 ngspice 경로를 사용한다.

표시한 회로 템플릿만 지원한다. 임의 배선·일반 회로 해석·실제 브레드보드 배선 재현이 아니다. 저항은 이상값이고 공차·온도·기생 성분은 모델링하지 않는다. LED는 일정 Vf 가정이며 실제 다이오드 모델·광출력 해석이 아니다. 정격 비교는 열 설계나 실물 안전의 승인이 아니다. 정적 퍼즐은 DRC/LVS/PEX·ngspice·실물 측정과 독립이다. 동적 퍼즐도 DRC/LVS/PEX는 각각 미실행이다.

## 검증과 다음 단계

`npm run test:study`로 미션별 수치·단위, 오배치, 중복 부품 금지, 정격 부족, 기록 재열기, revision 경계, 캐시·예산·동일 요청 재전달, 실패 질문 보존을 검사한다. 기존 배포용 backend bundle도 source tree 밖에서 실행한다. AI 테스트는 주입한 provider fixture이며 유료 실제 호출 검증으로 취급하지 않는다.

사용자 평가 전에는 학습 효과를 주장하지 않는다. 다음 우선순위는 학생의 예측·설명 평가, 실제 AI 응답 품질 점검과 추가 지원 소자의 실험이다.

## 커패시터·트랜지스터 실제 실험

9·10번 미션에서 부품을 꽂고 각 핀의 노드를 선택한다. 부품 종류·허용 연결·모든 필수 핀을 검사하며, **회로 확인하기**의 준비 상태는 해석 성공이 아니다. **ngspice 실제 실행 → 실행 상태 새로 확인**으로 별도 Edu 회로 사본을 만들고 공통 native schematic API와 과도해석·0 V sense-source 단자 전류 계측을 재사용한다. 새 수치 solver나 교육용 샘플 파형을 만들지 않았다.

- RC: 이상 R/C, 0↔1.8 V PULSE, 지연 1 µs, rise/fall 0.1 µs, high 20 µs, 주기 40 µs. 해석 40 µs / 최대 간격 20 ns, 27 °C. 1 kΩ/1 nF에서 시작해 C만 5 nF로 바꾼다. 시정수 식은 예측용이며 표시 파형은 실행 결과만 사용한다.
- NMOS: SKY130A `sky130_fd_pr__nfet_01v8`, TT, 1.8 V, 27 °C, L=0.15 µm, nf=m=1. 입력 지연 10 ns, rise/fall 1 ns, high 80 ns, 주기 160 ns. 해석 200 ns / 최대 간격 0.1 ns. D=OUT, G=IN, S=B=GND로 시작한다. G=GND 대조 실험과 C·풀업 R·MOS W 변경을 지원한다. BJT·PMOS 퍼즐과 자유 배선은 이번 범위에 포함하지 않는다.
- 커서의 보간은 공통 `packages/analysis/src/waveform.ts`를 사용한다. 전류는 첫 핀으로 들어가는 관습적 단자 전류이며 음수는 반대 방향이다. MOS 드레인 전류를 모든 단자의 동일 전류라고 가정하지 않는다.
- 각 실행은 조건·배치·연결·입력 서명·프로젝트 ID/revision·run ID·엔진 버전·모델·PDK 버전을 저장한다. 보드 수정 후 과거 파형에 이전 배치를 표시한다. 실선/점선은 선택 실행/직전 완료 실행이며 시간 커서는 전압과 전류에 공통이다.
- 엔진 없음/PDK 없음은 `unavailable`, 실제 도구 실패는 `failed`, 잘못된 결과 데이터는 `error`로 구분한다. 취소·대기·실행 중도 별도 상태다. 실패·미실행에 파형을 채워 넣지 않는다. 중단된 제출은 자동 재시도하지 않으며 명시적 상태 확인으로 오류를 보존한다.
- 저장 스키마 1에 선택 필드 `connections`, `simulations`를 추가했다. 설명은 작성 시 보드 revision·시간도 저장하며 이전 설명을 현재 배치의 답으로 바꾸지 않는다. 기존 작성 revision이 없는 설명은 미기록으로 표시한다. 새 undo 항목은 배치+연결 스냅샷이다. 기존 배치만 담긴 undo 항목도 읽고 기존 저항 실습을 보존한다. 한 세션 최대 20회 해석이며 기존 전체 20 MB 저장 한도도 유지한다.

`MOS_WORKSPACE`를 Edu 전용 공간으로 지정하고 `npm run test:puzzles:native`를 실행한다. 실제 RC 유한 상승 에지 해석식, 충전/방전 부호, KCL, C 변경, NMOS on·GND 대조·부하 변경과 재열기를 확인한다. [실행 증거](evidence/dynamic-puzzles/native-qa.json)에 모델·조건·원본 run 식별자를 기록한다.
