# Resistor Edu 온라인 이용 확인 — 클라이언트 전환 범위

정책 버전: `2026-11-13`. 이 문서는 새 소스의 동작과 전환 절차를 설명한다. 현재 공개 설치 파일이나 공개 인증·리그 서버에 이 정책이 배포되었다는 증거가 아니다.

## 기록과 의미

만 14세 이상인 이용자가 직접 확인하면 `schema_version`, `edition`, `policy_version`, `age_14_or_over: true`, `acknowledged_at`만 저장한다. 생년월일·신분증·이름을 추가하지 않는다. 연령 **자기 확인**이며 본인 인증이나 연령 검증 결과가 아니다.

- 설치 앱: 해당 제품의 Electron `userData/online-access-edu.json`.
- 로컬 Vite 개발 환경: 별도 Edu workspace의 `.runtime/online-access/online-access-edu.json`.
- Industry는 확인을 요구하지 않고 Edu 기록을 읽어 승계하지 않는다.
- 브라우저 단독 리그의 확인과 native host 확인은 저장 위치와 보안 경계가 다르다. 브라우저 localStorage 값이나 임의 RPC 입력을 native host의 권한으로 사용하지 않는다.

`online.access.status({})`와 `online.access.acknowledge({age_14_or_over: true, policy_version: '2026-11-13'})`는 시리얼 등록 전에도 호출할 수 있다. 저장 파일이 없거나 손상·다른 버전·다른 edition이면 확인되지 않은 상태다. 원래 라이선스와 프로젝트를 삭제하거나 수정하지 않는다.

## 첫 온라인 작업에서만 짧게 확인

`codex/edu-simple-20261113` 소스에서는 앱 시작 때 전체 화면 안내·연령 배너를 표시하지 않는다. 로컬 화면을 즉시 열고 원래 라이선스 검사는 별도로 유지한다. 유효한 기존 lease는 그대로 사용할 수 있으며, 새 인증이 필요한 경우 시리얼 화면은 여전히 표시된다. 연령 확인을 생략했다고 유료 사용권을 부여하지 않는다.

처음으로 인증·새 외부 AI 요청·리그 연결·공동 설계 연결 등의 **온라인 작업을 직접 선택했을 때**만 짧은 확인창을 연다. 체크박스는 처음부터 선택되어 있지 않다. 취소 또는 Escape는 전송 전 대기 중이던 작업을 취소하고, 화면·입력·시리얼 초안·기존 학습 기록을 유지한다. 확인창은 생년월일을 받지 않으며 포괄 개인정보 동의로 취급하지 않는다.

이 대기는 아직 전송되지 않은 원 요청 앞의 preflight다. 확인 후 host/browser에 실제 저장된 기록을 다시 검사한 뒤 해당 원 요청만 진행한다. 이미 실행된 요청을 재전송하거나 취소된 작업을 나중에 다시 실행하지 않는다. 동시에 다른 작업이 확인을 요구하면 한 번의 확인 뒤 여러 작업을 묶어 실행하지 않고 두 번째 작업은 취소한다. 확인창이 해제되면 대기 작업도 취소한다. 저장 실패는 진행으로 간주하지 않는다.

리그 snapshot/순위 갱신, 공식 서버 주소 자동 조회, 공동 설계 세션 복원·heartbeat는 미확인 상태에서 조용히 차단한다. 이 배경 동작은 확인창을 자동으로 열지 않는다. 리그 첫 화면의 `리그 연결`이나 `기록 새로고침` 등 직접 누른 동작만 확인을 요청한다. native 수동 업데이트 check/download도 preflight로 연결되며 host 검사를 우회하지 않는다. 브라우저의 공개 다운로드 안내와 일반 공개 페이지 접속은 별도 HTTP 요청이므로 ‘모든 네트워크가 0회’라고 표현하지 않는다.

## 실제 차단 위치

새 Edu main 프로세스와 Vite host는 확인 전 인증 서버의 activate/refresh 요청을 보내지 않는다. 앱 시작·매시간 refresh와 10초 후·6시간마다 자동 업데이트 조회도 건너뛴다. 수동 업데이트 check/download는 같은 host 확인을 통과해야 하며, 업데이트 전송 함수에도 가드가 있다. 시리얼·refresh secret이 요청 본문에 직렬화되기 전에 검사한다.

기존 유효한 서명 lease의 로컬 조회와 유효기간은 유지한다. 확인을 하지 않았다는 이유로 활성화를 취소하거나 인증 기록을 지우지 않는다. lease가 만료되었으면 새 온라인 확인 후 원래 refresh 절차가 필요하며 유효기간을 임의로 연장하지 않는다. 사용권 해제(deactivate)는 기존 자격 증명을 검증하는 별도 작업으로 계속 허용한다. 연령 확인 자체는 사용권이 아니므로 유료 앱 엔진 진입에는 원래 라이선스 검사가 그대로 필요하다.

외부 AI는 신뢰되는 host가 넘긴 함수로 실제 저장 기록을 읽고 공통 정책으로 재검증한다. `approved: true`나 요청 JSON의 연령 필드만으로 통과할 수 없다. 설계 리뷰, 문제 생성·주관식 채점, 퍼즐 AI 대화, Luna/Sol 학습 활동의 **새 외부 호출** 앞에서 검사한다. 비용 예약 전 검사하며, structured AI는 실제 전송 직전에도 다시 확인한다. 각 요청의 전송·비용 승인과 원래 예산 검사는 별개로 유지된다.

저장된 문제·캐시된 설명, 객관식 계산 채점, 규칙 코치, 기존 학습 기록, 로컬 회로·시뮬레이션 수식은 이 변경으로 가짜 결과를 만들거나 외부 호출을 요구하지 않는다. Ollama 주소는 기존 제한대로 기기 loopback만 허용한다.

## 기존 공개 버전과 서버 호환성

이번 변경은 **클라이언트/로컬 서비스 가드**다. 공개 `/v1/activate`, `/v1/refresh`, 리그 등록 프로토콜의 연령 필수 필드나 서버 강제는 추가하지 않았다. 새 클라이언트도 기존 서버에 기존 요청 형식을 전송한다. 따라서 공개 0.33 사용자가 갑자기 갱신 거절·활성화 취소를 당하는 서버 변경은 없다. 기존 공개 버전에 새 가드가 소급 적용되었다고 안내해서는 안 된다.

향후 서버가 증거를 받아야 한다면 별도 전환이 필요하다. 현재 리그 `league.enroll`은 strict params 스키마여서 임의 정책 필드를 추가하면 기존 서버가 거부한다. 인증 서버의 현재 알려지지 않은 필드 무시는 정책 저장·검증이 아니다. 클라이언트 버전 문자열만으로 이용자의 연령을 증명할 수도 없다.

1. 현재 활성화·리그 등록을 보존하는 서버의 선택적 정책 capability/수신·저장 계약을 먼저 합의한다.
2. 서버·신규 설치 앱의 실제 호환 검증과 새 다운로드 공개를 완료한다.
3. 기존 사용자 안내·확인 경로·적용 시점을 명시한 뒤 새 등록과 기존 refresh의 적용 범위를 따로 정한다. 기존 유효 lease를 일괄 취소하지 않는다.

CLI/MCP에서 Edu 외부 AI 서비스를 직접 호출할 때 host callback이 없으면 새 호출은 차단된다. 기존 명령의 단순 `approved: true`를 연령 확인으로 간주하지 않는다. 운영자 리그 AI 출제 등 별도 CLI 확인 연결은 후속 범위이며, 저장 문제 재사용·계산·조회는 계속 가능하다. 촬영 리허설은 원래 외부 AI 호출이 금지되어 있으므로 그 제한을 완화하지 않는다.

## 검증 범위

`node --test tests/desktop-online-access.test.mjs`는 합성 데이터·가짜 provider와 로컬 테스트 인증 서비스만 사용한다. 최소 기록과 재열기, edition 격리, 손상·오래된 정책 거부, 자동 호출 0회, direct 인증 우회 차단, 기존 lease 바이트 보존, 해제 허용, AI 전송/비용 예약 차단, 로컬 객관식 채점 유지가 대상이다. 실제 Gmail·인증 서버·OpenAI·공개 리그에 데이터를 보내거나 운영자 계정을 변경하는 테스트가 아니다.

`tests/online-access-presentation.test.mjs`는 실제 Boundary와 요청 대기 코드를 함께 실행하여 시작 시 로컬 화면 유지, 배경 검사 무프롬프트, 직접 선택 후 미전송 대기, 취소/Escape·초안 유지, 저장 후 원 요청 1회 진행, 동시 작업 비합류, 저장 실패와 unmount 취소를 확인한다. `tests/online-access.test.ts`와 `tests/online-cloud-access.test.mjs`는 실제 요청 경계에서 미확인 payload 전송 0회·host 기록 재검증·리그 키 등록 전 차단·공동 설계 credential 보존을 검사한다. 이 합성 검사는 실제 운영 사용자의 자기 확인이나 배포 완료를 뜻하지 않는다.

새 설치 앱 4개 OS 실행·배포, 실제 서버 enforcement, 기존 사용자 전환은 이 소스 검사만으로 완료 처리하지 않는다.
