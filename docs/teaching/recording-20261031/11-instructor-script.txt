Resistor Edu · 11 오류를 만들고 원인 찾기
목표 10분 (시연 포함·계획) · 강사 직접 녹음 · 아직 녹화하지 않은 대본
오래된 결과와 검사 실패·도구 오류를 구분한다.

그래프가 있다는 것만으로 현재 회로의 결과라고 볼 수 없습니다. 지금 입력을 바꿨지만 아직 다시 계산하지 않았습니다. 이전 결과가 사라지는 대신 어느 revision의 결과인지 남아 있어야 비교할 수 있습니다.
도구가 실행되지 않은 상태, 도구 실행 자체가 실패한 상태, 실행은 끝났지만 검사가 불합격인 상태도 나눠야 합니다. 예를 들어 Magic이 실행되어 위반을 찾았다면 도구 오류가 아니라 검사 결과입니다. 시뮬레이션 한 번의 성공이 DRC·LVS·PEX를 모두 통과했다는 뜻도 아닙니다.
질문을 보낼 때에는 화면 한 장뿐 아니라 edition, 프로젝트 revision, 입력 조건, 실행 ID와 오류 내용을 같이 보내주세요. API 키나 시리얼 코드는 보내지 않습니다. 재현할 수 있는 질문을 만드는 것도 설계 실습의 일부입니다.

화면 조작
1. 계산 이후 입력만 바꿔 stale 표시를 확인한다.
2. 이전 결과를 지우지 않고 현재 조건을 다시 실행한다.
3. 별도 QA 예제의 실제 DRC/LVS 불합격 로그를 읽는다.
4. 오류 보고에 필요한 조건·run ID·재현 절차를 적는다.

학생 멈춤 질문: completed + fail은 도구가 실행되지 않았다는 뜻인가요?
결과물: 재현 가능한 오류 보고서 1장
