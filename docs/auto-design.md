# Resistor Indust · AI 오토 설계

**설계 도구 → AI 대화·검토 → AI 오토 설계**에서 목표를 입력하고, 후보 회로를 확인한 뒤 실제 로컬 엔진으로 비교합니다. Luna(`gpt-6-luna`)는 요청의 지원 범위를 판단하고 Sol(`gpt-6.1-sol`)은 고정된 회로 구조의 수치 후보를 작성합니다. 회로 생성·공식·단위 검증·수치 측정은 native 엔진이 수행합니다.

## 시작하기

1. 로컬 엔진을 연결하고 **설계 엔진·AI 연결 확인**을 누릅니다. OpenAI 키와 사용자가 설정한 누적 예산이 필요합니다. 새 작업공간의 기본 유료 호출 예산은 US$0입니다. 키는 서버/메인 프로세스에만 보관합니다.
2. 설계군, 후보 수(1–3), 공급 전압, 칩 영역 제한과 목표 범위를 입력합니다. 예: DUET-AFE, 1.8V, 300×300µm, 저속 이득 3.8–4.2V/V, 저속 대역폭 4–6kHz, 고속 대역폭 80–120kHz, 동작점 공급 전력 500µW 이하.
3. 이번 API 전송에 동의하고 **AI 후보 설계·미리보기**를 누릅니다. 이때 회로 생성이나 시뮬레이션은 실행하지 않습니다. 정보가 부족하면 Luna의 확인 내용이 표시되고 Sol은 호출하지 않습니다.
4. 각 후보의 파라미터·근거 가설·실제 하위 셀·소자 수·SPICE 미리보기를 확인합니다. 미리보기의 칩 크기는 설계 제한이며 실제 배치 면적이 아닙니다.
5. 저장된 실행 조건·목표와 후보를 확인하고 실제 생성·해석 승인에 체크한 뒤 **승인하고 생성·시뮬레이션·비교**를 누릅니다. 후보마다 별도 프로젝트를 만들고 설계군에서 지원하는 실제 해석을 순서대로 실행합니다. 기존에 열어둔 프로젝트는 수정하지 않습니다.
6. 비교 표에서 측정값과 `충족 / 미달 / 미측정`을 확인합니다. **이 회로 열기 · 회로도/파형**은 편집 가능한 프로젝트와 비교에 사용한 nominal 과도 해석을 엽니다. 과도 해석이 없는 설계군은 프로젝트만 엽니다. 자세한 파형·부호 있는 전류·전압 강하는 기존 시뮬레이션 패널에서 확인합니다.

입력 폼을 바꾸어도 이미 저장된 실험의 목표·조건은 바뀌지 않습니다. 변경된 조건은 새 후보 계획으로 만드세요. 후보가 목표를 놓쳐도 실측값과 실패 기록을 보존합니다. 목표 충족은 지정된 회로도 측정 기준에만 해당합니다.

## 지원 범위

| 설계군 | 조정 범위 | 실제 분석 |
| --- | --- | --- |
| DUET-AFE 이중 대역 센서 입력부 | 폐루프 이득, 두 RC 극점, 보상 C/R, 바이어스 저항 | OP·AC·tran |
| IVR 온칩 LDO | 0.6V 기준·1.2V 목표·20→200µA 부하는 고정; 패스 뱅크·바이어스·보상·출력 R/C 비교 | OP·AC·tran |
| RC 저역통과 | R, C 및 native catalog의 허용 파라미터 | OP·AC·tran |
| Miller OTA | native catalog의 OTA 파라미터 | OP·AC |
| 2극 필터 | native catalog의 필터 파라미터 | OP·AC·tran |
| TIA | native catalog의 TIA 파라미터 | OP·AC·tran |

정확한 허용 키·기본값은 연결한 엔진의 catalog가 결정합니다. native 범위 밖 값·없는 파라미터·중복 회로는 거절합니다. 자유로운 MOS 토폴로지 생성, 임의 배선/P&R, 레이아웃 자동 합성은 이 기능의 지원 범위에 포함하지 않습니다. 임의 SPICE나 셸 명령을 모델에서 받아 실행하지 않습니다. 현재 오토 설계의 제공자는 OpenAI이며 기존 일반 대화의 Ollama 선택과 구분합니다.

## 상태·복구·비용

- 모델 출력은 가설입니다. 비교 표에는 해당 프로젝트·revision·분석·공정 코너·온도·전압이 일치한 native 결과만 사용합니다. 누락·NaN·실패를 성공으로 바꾸지 않습니다.
- 후보 실행 수를 미리 제한하며 최대 3후보×3해석입니다. 각 해석의 대기 한도는 180초이며 초과 시 실제 취소를 요청합니다.
- **저장된 자동 설계**에서 복원하고 JSON으로 내보낼 수 있습니다. 엔진 실행 중 프로세스가 끊기면 자동 재실행하지 않으며, 명시적 재개 시 command receipt로 기존 프로젝트/job을 복구합니다. 같은 요청을 재전송해 중복 회로·해석을 만들지 않습니다. 모델 호출 중 중단된 계획은 새 요청으로 시작하며 유료 호출을 자동 재개하지 않습니다.
- **실행 취소**는 현재 job의 실제 취소를 요청하고 다음 후보/해석 시작을 막습니다. 이미 끝난 결과는 남깁니다. 취소한 실험은 새 계획으로 시작합니다.
- Luna/Sol은 동일한 원자적 누적 예산 ledger를 사용합니다. 역할별 최대 비용을 각각 예약하며 표시 금액은 최종 청구액이 아닙니다. API 실패 시 자동 유료 재시도·모델 교체를 하지 않습니다.
- 기록은 해당 제품 작업공간의 `.runtime/assistant/auto-designs/`에 저장합니다. Edu/Indust의 프로젝트·키·기록을 합치거나 복사하지 않습니다. 공동 설계 방에도 로컬 키를 전달하지 않습니다.

## 직접 설계하고 실행한 DUET-AFE

[회로·편집 프로젝트·측정 그림·재현 절차](../examples/duet-afe/README.md)를 제공합니다. 실제 앱에서 Luna/Sol 각 1회, 후보 2개, native 해석 6회를 실행했습니다. 저전력 후보를 추가 두 MOS PVT 조건에서 6회 검사했고, 기본 회로의 9회를 합해 총 **21회 실제 ngspice 해석**을 보존했습니다.

TT/1.8V/27°C에서 선택 후보는 저속 이득 4.00325V/V, 저속 대역폭 4.99723kHz, 고속 대역폭 99.4577kHz, 동작점 공급 전력 353.127µW였습니다. 같은 조건의 기본 후보 대비 전력은 18.53% 감소했습니다. 두 후보를 비교한 결과이며 전역 최적해라는 의미는 아닙니다.

이 설계는 이상적 R/C를 사용하는 SKY130 MOS 회로도 프로토타입입니다. 잡음·오프셋/소자 편차·RC 공정 변화·배선 기생·물리 면적·제조 signoff는 미검증입니다. 빈 레이아웃에 DRC/LVS/PEX를 요청하면 `NO_PHYSICAL_LAYOUT`을 반환하며 PASS를 만들지 않습니다.

검증: [최종 검사 요약](evidence/auto-design-20261029/verification.json) · [실제 API·앱 조작 기록](evidence/auto-design-20261029/ui-workflows.json) · [실제 native 후보/PVT·내보내기 검증](evidence/auto-design-20261029/qualification.json) · [실제 비교 화면](evidence/auto-design-20261029/actual-comparison.png). 새 설치 파일·운영 사이트 배포는 별도입니다.

```sh
npm run test:assistant
npm run test:core
npm run typecheck
npm run build:indust
npm run build:edu
node scripts/duet-afe-lab.mjs --generate
```

마지막 명령은 유료 API를 호출하지 않고 격리된 native 작업공간에서 기본 DUET-AFE를 생성·해석합니다. Python·ngspice·공개 SKY130 모델이 준비되어야 합니다. 이미 승인·실행된 AI 실험은 `node scripts/auto-design-qualify.mjs --workspace=<실험 작업공간> --design-id=<실험 ID>`로 추가 검사할 수 있습니다. 이 명령 역시 모델 호출 없이 실제 엔진만 사용합니다.
