# Resistor Edu · 재연결과 프로젝트별 학습 대시보드

2026-10-19 · Edu 소스 개발판. 실행은 `npm run dev:edu`이며 메인 또는 상단
**학습 프로젝트**에서 연다. 기존 학습 저장소와 공통 EDA 엔진을 재사용한다.
현재 대상은 서버에 저장되는 CMOS 인버터 연결 실습이다. 퀴즈 이력과 기기 로컬의
과제 패키지 기록은 각 기존 학습 화면에서 확인한다.

## 내 학습 프로젝트

- 기본 목록은 학생 실습과 용도가 미지정된 이전 기록이다. 용도 없는 이전 기록을
  학생 제출물로 추정하지 않는다. 검증용 사본은 **QA 사본 포함**에서 별도로 확인한다.
- 프로젝트마다 현재 조회 revision과 기록 revision, 부하·모델 조건, 설명 저장 기준,
  기기에 보관한 입력 초안, 변경 전후 실행 ID·상태·현재성을 구분한다.
- DRC·LVS·PEX는 각각의 실제 실행을 표시한다. 검사 불합격 `completed/fail`, 도구
  오류 `failed/unknown`, `not_run`, `unavailable`을 합치지 않는다. 기록된 도구와
  공정 정보는 기록 당시의 식별 정보이며 최신 설치 확인과 다르다.
- 엔진 조회가 실패하면 현재 revision은 `null`, 실행 현재성은 `unknown`이다.
  저장된 실행 조건이 있으면 **이전 실행 입력**, 없으면 **입력 확인 필요**로 표시한다.
- 브라우저와 서버 사이의 조회 자체가 실패하면 직전 화면을 유지하면서 **마지막 조회·
  현재성 미확인**으로 표시한다. 마지막 수치나 PASS를 현재 결과로 바꾸지 않는다.
- **이 실습 이어가기**는 해당 실습 ID와 기기에 남은 페이지를 함께 연다. 저장된
  페이지가 없으면 관찰·기준 해석·조건 변경 등의 추천 위치로 이동한다. 이 위치는
  학습 완료 판정이 아니다. 새 실습 선택은 1단계를 열며 프로젝트를 자동 생성하지 않는다.

주소는 `#projects`, `#design/5/lesson/<lesson UUID>` 형태다. 기존 `#design/1`–
`#design/7`와 화면 위치 저장 형식도 지원한다. 새로고침·이전/다음·프로젝트 전환에서
대상 실습 ID를 유지한다. 다른 실습을 읽는 중에는 이전 프로젝트를 편집 대상으로
표시하지 않는다.

현재 페이지의 이름·프로젝트/실습 ID를 검색할 수 있고, 20건씩 페이지를 이동한다.
기기 초안은 서버 입력과 별도다. 값이 같다고 회로 적용 여부를 추정하지 않는다.
초안 충돌·형식 오류는 기존 [초안 비교·복원](edu-continuation-review.md)을 사용한다.

## 연결 실패 후 같은 화면에서 계속하기

- **문제 은행 다시 연결**: 저장 문제와 학습 이력만 다시 읽는다. 선택 문제·작성 답안·
  피드백을 유지한다. 같은 저장소 잠금을 쓰는 두 조회는 순서대로 수행한다.
- **실습 기록 다시 연결**: 목록과 현재 실습만 다시 읽는다. 기존 초안은 유지하며,
  다른 창에서 저장한 설명과 충돌하면 먼저 비교한다. 필요하면 기존 엔진 진단을 연다.
- **프로젝트 상태 다시 읽기**: 현재 목록의 저장 메타데이터와 엔진 상태를 조회한다.
- 실행 중 상태 조회가 실패하면 반복 조회를 멈춘다. 사용자가 재연결하면 같은 실행
  ID의 상태를 읽고, 여전히 실행 중인 경우에만 상태 조회를 재개한다.

재연결은 실습 생성·회로 변경·해석 제출·학생 제출·AI 생성/채점을 자동 재실행하지 않는다.
유료 API 동의나 키 설정을 바꾸지 않는다. 같은 읽기 작업의 중복 시작은 공유하고,
다른 프로젝트·필터의 늦은 응답은 현재 화면에 적용하지 않는다.

## 읽기 API와 호환성

`learning.dashboard`는 `{include_qa?: boolean, offset?: number, limit?: number}`를
받는다. 기본값은 `false, 0, 20`, 최대 limit은 50이다. Edu 작업 공간에서만 허용한다.
응답에 `schema_version`, `edition`, `product_id`, 조회 시각·범위·총수·경고와
실습별 프로젝트·revision·엔진·공정 식별 정보를 포함한다. 학생 답안 원문은 반환하지 않는다.
MCP의 `register_learning_dashboard`도 같은 응답을 읽기 전용 도구로 제공한다.

엔진 조회는 프로젝트별로 한 번, 동시 최대 4개, 전체 대기 약 5초로 제한한다.
시간 초과 시 실제 실행 없이 저장 메타데이터로 응답한다. 손상된 실습 파일은 경고로
격리하고 원본과 정상 기록을 보존한다. `learning.list`는 기존 필드를 유지하면서
`purpose`와 `warnings`를 추가했다. 서버 기록 schema와 저장 경로는 변경하지 않았다.
Indust 데이터·수식·기하·파일 엔진·설치 파일은 변경하지 않았다.

## 검증

- 실제 Edu 기록을 대상으로 정상 엔진 → 도달하지 않는 주소의 엔진 → 정상 엔진
  조회를 수행했다. 설정 파일을 바꾸거나 작업 엔진을 중단하지 않았다.
- 대시보드 조회 전후 전체 학습 기록 파일의 바이트가 같았다. QA 프로젝트 r2,
  실제 5 fF와 기기 초안 95 fF를 구분했고 새 해석 trial은 생성하지 않았다.
- 브라우저 네트워크 장애를 주입해 최초 문제 은행 실패, 재조회 실패 후 답안 보존,
  실습 초안 보존, 대시보드 마지막 조회 표시와 수동 복구를 확인했다. 장애 설정은 복원했다.
- 별도 QA 프로젝트 두 개의 실습 ID 이동, 새로고침과 브라우저 뒤로가기를 확인했다.
  이전 QA의 실제 해석 기록은 관찰했으며 새 시뮬레이션·공용 리그 글·학생 답안을 제출하지 않았다.
- 390×844 화면에서 가로 넘침 없이 상단 4개 모드와 대시보드를 확인했다.
- Core 323건, edition/MCP 9건, typecheck, Edu·Indust 빌드를 통과했다.
  기존 대형 bundle 경고는 남아 있다. 새 native 설치 파일은 배포하지 않았다.
