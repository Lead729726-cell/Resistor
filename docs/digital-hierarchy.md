# 가산기와 작은 CPU · 레지스터 0.13

`가산기·CPU`에서 공개 SKY130 회로를 만듭니다. 원래 프로젝트는 보존됩니다. 생성된 회로도, 하위 셀, 트랜지스터와 배선은 편집할 수 있습니다.

| 설계 | 회로 | 실제 입력 검증 |
| --- | --- | --- |
| 1비트 전가산기 | 9 NAND2, 36 MOS. XOR의 NAND 항을 carry와 공유합니다. | A/B/CIN의 8개 조합 |
| 4비트 가산기 | FA 하위 셀 4개, 144 MOS. A+B+CIN, ripple carry. | 512개 조합 |
| 작은 CPU | ACC/PC 각 4비트, carry 레지스터, zero 출력, 16×6비트 ROM. | 16개 명령, 실제 PC/ROM/ACC/flags 및 안정 구간 |

CPU의 명령은 `LOAD`, `ADD`, `AND`, `XOR`와 0~15 즉시값입니다. 각 클럭의 상승 에지에서 실행합니다. PC 15 다음에는 0으로 돌아갑니다. RESET은 클럭 동기식입니다. ADD는 4비트로 순환하며 carry를 저장합니다. 다른 연산은 carry를 0으로 만듭니다. 외부 RAM, 분기, halt, 인터럽트, 범용 CPU ISA는 아직 포함하지 않습니다.

기본 예제는 LOAD 3 → ADD 5 → ADD 9 → XOR 10 → AND 7 → LOAD 15 → ADD 1 → ADD 15 → AND 6 → XOR 15 → LOAD 0 → ADD 7 → ADD 8 → XOR 5 → AND 10 → LOAD 4입니다. ROM 내용은 생성 화면에서 바꿀 수 있고 실제 CMOS decoder를 생성합니다. 출력값을 미리 계산해 전압원에 넣는 방식은 사용하지 않습니다.

기본 클럭/입력 유지 시간은 50 ns입니다. CPU의 앞 두 클럭은 reset에 사용합니다. 실측 결과로 16개 명령을 검사합니다. 검증 코드는 생성 코드와 별도의 계산으로 예상 결과를 만들며 실제 입력도 함께 확인합니다. 0.3 VDD 이하와 0.7 VDD 이상으로 논리를 판정합니다. 중간 전압, 부족한 구간 또는 누락된 파형은 통과시키지 않습니다.

물리 배치는 실제 SKY130 MOS PCell과 via, met2/met3 배선을 사용한 넓은 참조 레이아웃입니다. 회로도의 전가산기·게이트·레지스터 계층과 물리 도형의 계층은 동일하지 않습니다. 면적 최소화, 모든 PVT·부하의 타이밍, 제조 signoff를 완료한 제품 셀은 아닙니다. 1비트 가산기의 DRC/LVS와 100 ns 조건의 실제 RC post-layout 검증은 독립적으로 실행합니다. 0.13에서는 CPU 전체 DRC/LVS/PEX를 검사하고 constant gate/body 단락을 수정했습니다. RC 동작은 클럭별 실제 판정을 별도로 기록하며 timing closure와 구분합니다. [현재 설계·물리 조건·실패 기록](../examples/cpu4/README.md).

내부 물리 넷은 Magic RC 노드 표기와 충돌하지 않는 이름을 사용합니다. 전기적 하위 경로와 device ID는 유지합니다. PEX 결과에서 음수·비정상 R/C를 삭제하거나 값을 보정해 통과 처리하지 않습니다.

전체 CPU RC 동작은 TT·27°C·1.8V·5fF·400ns 조건에서 16/16을 통과했습니다.
50ns의 RC 실패와 200ns의 14/16 결과는 보존합니다. 기본 50ns 회로 예제와
`cpu4-rc-400ns.register-project.zip`의 물리 통과 예제를 구분하세요.

## 계층 복사와 승인

회로도의 `계층 복사`는 현재 루트 또는 선택한 하위 셀을 앱의 로컬 clipboard에 저장합니다. `계층 가져오기·미리보기`에서 붙여넣거나 다른 저장된 프로젝트를 선택합니다. 원본 revision을 확인하고, 새 namespace, 대상 셀, 위치, 회전, 미러, 포트별 넷 연결을 지정합니다.

- 같은 PDK와 DBU만 함께 가져옵니다. 기존 셀 정의를 덮어쓰지 않습니다.
- 하위 셀의 의존 셀과 실제 물리 cell tree를 복사합니다. 물리 대응이 없는 하위 셀은 회로도만 가져오기 범위를 직접 선택해야 합니다.
- `현재 설계를 상위 셀로 감싸기`는 현재 루트를 MAIN 하위 블록으로 넣고 기존 포트를 유지합니다. 부모의 핀 주석을 추가하지만 실제 mask polygon의 합집합이 유지되는지 검사합니다.
- 전체 상위 루트를 펼친 현재/적용 후 도형을 비교합니다. 공유 하위 셀의 모든 사용 위치가 포함됩니다. 100,000개 도형을 넘으면 부분 결과를 승인할 수 없습니다.
- 전체 native polygon 합집합으로 레이어별 추가·삭제 면적과 새 도형의 같은 레이어 겹침을 계산합니다. 겹침이 DRC 위반이나 전기적 단락을 뜻하는 것은 아닙니다. 표시 상자는 최대 256개이고 총 개수와 도형은 모두 계산합니다.
- 핀 연결은 회로도에 반영합니다. 블록 사이의 물리 배선은 자동 생성하지 않습니다. 공급선과 신호선을 실제로 연결하고 DRC/LVS/PEX를 다시 실행해야 합니다.
- 미리보기는 파일이나 revision을 변경하지 않습니다. 명시적 체크와 `승인·적용`으로 한 revision을 생성합니다. 입력, 원본, 대상이 달라지면 오래된 승인은 거부합니다. Undo/Redo와 command 재전송 중복 방지를 지원합니다.

Canvas 경로는 한 번 만들어 재사용합니다. 확대·이동에 수만 개 React DOM을 만들지 않습니다. 저장된 원본 검색은 큰 파형을 불러오지 않고 compact metadata만 읽습니다. 미리보기 서버 cache는 도형 사본을 중복 보관하지 않습니다. 적용 전 3D와 레이어별 확인도 가능합니다. 레이어 높이는 기존 viewer의 표시용 값이며 공정 topography 검사는 별도 공정 3D 기능을 사용합니다.

큰 디지털 설계를 열 때는 전체 도형 표시를 기본으로 선택하고 이전 프로젝트의 영역·넷 강조를 해제합니다. 현재 예제 CPU는 73,005개 도형을 모두 읽어 GPU 도형 생성까지 확인했습니다. 이 PC의 추가 검증 영상에서 전체 mesh 준비는 약 26초 걸렸습니다. 준비 진행 표시가 끝난 후 전체 모델을 확인해야 하며, 이 시간은 다른 PC의 성능을 보장하는 수치가 아닙니다.

## 저장과 작업 기록

회로도, 설정, 실제 레이아웃은 `.register-project.zip` bundle에 보존됩니다. GDS만으로 CPU 프로그램이나 회로 해석 조건을 복구할 수는 없습니다. 실제 앱에서 만든 예제와 녹화는 `examples/cpu4/`에 저장합니다. 녹화 범위는 로컬 앱 화면이며 개발 터미널 전체를 영상으로 캡처한 것은 아닙니다. D: 분리 전 프레임과 CPU 실행 시간 제한을 발견한 첫 시도 영상도 별도로 보존합니다.

`examples/cpu4/replay.html`에서 완료한 작업과 별도의 전체 CPU 3D 준비 영상을 재생합니다. 첫 작업 영상의 3D 구간은 준비 도중 화면을 전환했으므로, 전체 도형 완료 화면은 추가 영상과 `preview-verification.json`을 함께 확인합니다.

검증 명령: `npm run test:digital-hierarchy`, `npm run test:cpu-physical`, `npx playwright test tests/ui/digital-hierarchy.spec.ts`, `npm run test:semiconductor-starters`, `npm run test:mcp`, `npm test`, `npm run build`. [5단계 검증 화면과 설치 진단](validation-workflow.md).

상용 도구가 설치되지 않은 서버의 Virtuoso/Custom Compiler/Calibre 실행, 실제 제조 signoff, Mac에서의 실행은 이 검증으로 완료 처리하지 않습니다. 인터넷 배포는 진행하지 않습니다.
