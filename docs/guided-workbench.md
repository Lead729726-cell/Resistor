# Resistor · 단계별 작업 화면

Resistor Indust의 설계 작업대와 Edu가 사용하는 공통 설정 화면을 단계별 팝업으로 정리했습니다. 계산식·회로 연결·파일 형식·엔진 호출은 기존 동작을 사용합니다. 교육 실습 완료 표시와 실제 엔진 검증 결과는 서로 다릅니다.

## 작업 시작

작업대에는 현재 프로젝트, 보기 전환, 저장, 탐색·선택 속성·결과, 해석·검증 준비를 둡니다. **작업 시작**을 누르면 프로젝트, 설계와 검토, 공정과 파일, 작업 환경 중 하나를 선택합니다. 한 번에 최대 네 가지 도구가 보이며, 나머지는 **다음 도구**로 이동합니다.

팝업 상단의 **이전 화면**은 상위 작업으로 돌아갑니다. 설정 안의 **이전·다음**은 같은 작업의 설정 단계를 이동합니다. 단계 이동으로 프로젝트를 생성하거나 해석을 시작하지 않습니다. 닫기 버튼을 누르면 작업대로 돌아가며, 키보드 초점도 작업을 연 버튼으로 돌아옵니다.

## 새 프로젝트와 미리 준비된 반도체

**작업 시작 → 프로젝트 → 새 프로젝트**에서 시작 회로를 고르고, 이름을 입력한 다음 생성 내용을 확인합니다. 마지막 화면의 **프로젝트 생성**을 눌러야 새 설계가 만들어집니다. 이름 입력에서 Enter를 누르면 먼저 확인 화면으로 이동합니다.

**작업 시작 → 프로젝트 → 다음 도구 → 내 반도체**는 설계 종류, 회로, 공정, 시작 조건, 생성 확인 순서입니다. 회로 종류는 한 페이지에 네 개, 회로 선택지는 세 개씩 표시합니다. 이름과 운전 조건은 이전 단계로 갔다 돌아와도 유지됩니다. 공정이 준비되지 않았다면 실제 생성과 실행이 가능한 것처럼 표시하지 않습니다.

## 해석 조건과 실행

**해석·검증 준비**에서 실행할 작업을 고르고 조건을 확인한 후, 마지막 화면에서 실제 엔진을 실행합니다. 실행 준비 화면의 **전원·온도·시간 조건 설정**은 다음 네 화면으로 구성됩니다.

1. 해석 종류와 모델 코너
2. 전원·온도와 MOS 바이어스
3. 관찰 시간·시간 간격·출력 부하
4. 조건 확인과 명시적 저장

각 입력 옆의 단위를 확인하세요. 저장 전 단계 이동은 설계 revision이나 실행 이력을 바꾸지 않습니다. 범위를 벗어나거나 유한하지 않은 수치는 다음 단계와 적용을 막습니다. 조건을 저장한 뒤 실제 해석은 별도의 실행 버튼으로 시작합니다.

## PDK와 GDS 해석

**작업 시작 → 공정과 파일 → PDK·해석 설정**에서 공정 선택, 실제 리소스 검증, GDS 추출 검사, 포트별 바이어스, 해석 종류, 범위, LVS reference, 검토·저장, 실행 결과 순서로 진행합니다. 필요한 검사가 끝나기 전에는 다음 설정으로 진입할 수 없습니다.

새 PDK를 작성할 때는 식별 정보, 검증 deck 경로, 모델 정보를 각각 다른 화면에서 입력합니다. 이동 중 입력은 유지되지만 **Profile 등록 / 검사**를 누르기 전에는 서버에 등록하지 않습니다. 입력 완료는 파운드리 승인이나 모델 검증 통과를 의미하지 않습니다.

## 속성과 실제 결과

회로도에서는 **＋ 소자**로 종류와 배치 값을 고르고 캔버스로 돌아옵니다. 실제 캔버스를 클릭해야 소자가 추가됩니다. **도구·설정**은 그리기·선택 편집·계층·로직·연결 해석을 각각 다른 화면에 표시합니다. 선택·배선·전체 맞춤 같은 자주 쓰는 동작과 기존 키보드 단축키는 작업 화면에서 바로 사용할 수 있습니다.

레이아웃은 **도구**에서 사각형·다각형·배선을 고른 뒤 레이어·연결 이름·배선 폭을 설정합니다. **설정 완료·캔버스로**를 눌러 도형을 그리며, 다시 **그리기 설정**을 열면 입력이 유지됩니다. **편집 → Box 추가**의 수치 입력은 좌표와 레이어·연결을 다른 화면으로 나누며, 마지막 **명령 적용**에서 저장합니다. 보기·레이어·내보내기도 별도 팝업으로 엽니다.

회로 소자나 레이아웃 도형을 선택한 뒤 **선택 속성**을 엽니다. 미적용 소자 입력은 동일한 앱 세션에서 팝업을 닫았다 열어도 유지됩니다. 현재 서버 값과 충돌하는 입력은 기존 비교·적용 절차로 확인합니다. 앱 종료 후까지 보존되는 저장 데이터와는 다릅니다.

**결과**는 실제 작업 상태, revision, 엔진, 로그와 결과 파일 위치를 보여줍니다. 미실행, 실행 중, 완료, 실패와 오래된 revision의 결과를 구분합니다. 팝업의 다음 단계에 도달했다는 이유로 DRC/LVS/PEX 또는 시뮬레이션이 PASS로 바뀌지 않습니다.

## 재검증

`node tests/integration/guided-workbench.mjs`는 격리된 Resistor Indust 프로젝트와 테스트 전용 라이선스로 브라우저를 실행합니다. 이전·다음 이동의 비변경성, 입력 보존, 실행 승인 지점, 데스크톱·모바일·라이트 테마, 실제 ngspice RC 해석을 확인합니다. 운영 라이선스나 사용자 설계는 사용하지 않습니다.

화면 캡처와 실행 기록은 [검증 디렉터리](evidence/guided-workbench-20261031/ui-verification.json)에 보관합니다. 이 UI 검사는 상용 엔진 실행이나 제조 signoff 검증을 대신하지 않습니다.

## AI·HDL·통합 도구

AI 도우미는 도움 방식 선택 → 설계 근거와 제공자 확인 → 질문·검토·계획 순서입니다. 빠른 점검과 실제 전압·전류 근거는 별도 깊이에서 열고 돌아옵니다. 뒤로 이동해도 질문 초안은 유지되며 전송 승인은 해제됩니다. 자동 설계는 연결 → 회로·전원 → 칩 제약 → 측정 항목별 규격 → 요청 → 모델 호출 승인 → 후보별 검토 → 실제 생성·해석 승인 순서입니다. Luna/Sol 계획도 요청, 모델 승인, 영향 검토, 실제 적용을 구분합니다. 탐색만으로 API나 해석을 실행하지 않습니다.

HDL은 예제 → 파일별 소스 → 테스트 벡터 → 칩 제약 → 저장 검토 → 실행 선택을 거칩니다. 상태·결과·아날로그 연동은 별도 화면입니다. 통합 도구는 작업 선택에서 출발하며 PVT와 라우팅도 조건별 단계와 마지막 실행을 분리합니다. 이전 화면으로 돌아가도 미저장 입력을 보존합니다.

`tests/integration/assistant-chat.mjs`의 모델 응답은 로컬 제공자 경계 검사용 fixture입니다. 실제 모델의 설계 품질이나 상용 엔진 검증을 의미하지 않습니다. 이 테스트는 유료 OpenAI 호출을 하지 않습니다.

최종 확인: 작업대 36개, 고급 도구 41개, AI 22개, 강의 Indust/Edu 각 19개의 브라우저 검사를 통과했습니다. [전체 검증 요약](evidence/guided-workbench-20261031/validation-summary.json)과 [고급 도구 검증](evidence/guided-advanced-20261031/ui-verification.json)에 실행 범위를 기록했습니다. 두 에디션 빌드를 확인했으며, 이 변경에서 새 설치 파일이나 운영 사이트를 배포하지는 않았습니다.
