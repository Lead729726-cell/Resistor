# Resistor Edu · Luna 판단 → Sol 학습 활동

Edu의 목표는 학생이 예측하고, 직접 계산·실험하고, 이유를 설명하고, 조건 하나를 바꿔 다시 확인하는 것이다. Industry의 전문 설계 검토 흐름과 구분하며, 회로·수학·기하·파일·실행 엔진은 공유한다. 교육 효과는 아직 사용자 평가로 검증하지 않았다.

## 실제 구현과 사용

Node.js 24에서 `npm run dev:edu`로 실행한다. 기존 시리얼 인증은 유지된다. 퀴즈·자율학습의 문제 화면 또는 회로 퍼즐의 ‘코치 모드 → Luna 판단 → Sol 학습 활동’을 연다.

1. 직접 답안 또는 예측을 쓰고 힌트·개념·비교 실험 중 목표를 고른다.
2. ‘전송 내용·최대 비용 확인’을 누른다. 입력 조건, 현재 계산/실행 근거, 캐시 유무, 두 단계 합계의 최대 예약 비용을 읽는다. 이 조회는 AI를 호출하지 않는다.
3. 새 호출이 필요할 때 해당 입력과 비용을 승인한다. 기본 학습 상한은 0이며 자동으로 올리지 않는다. 문제 은행 하단 ‘AI 문제 세트·비용 설정’에서 사용자가 직접 정한 범위만 사용한다. 기존 승인된 키 참조를 재사용하며 키를 Edu에 복사하지 않는다.
4. Luna 판단 후 Sol 안내를 읽는다. 관찰한 사실 → 규칙/모델 → 판단 근거 → 다음 활동으로 표시한다. Luna가 근거 부족을 반환하면 Sol 단계는 생략한다.
5. 실제 계산·시뮬레이션은 기존 버튼으로 직접 수행한다. AI가 회로를 바꾸거나 엔진 작업을 제출하지 않는다.
6. 학생이 ‘내 이유 설명’을 작성해 저장한다. 활동 기록을 불러오면 원문과 당시 조건을 다시 연다. 새로고침과 기록 조회는 외부 AI를 호출하지 않는다.

| 역할 | 모델 | 허용한 작업 |
| --- | --- | --- |
| 학습 판단 | `gpt-6-luna` | 학습 초점과 힌트·개념·실험 또는 추가 근거 요청 선택 |
| 활동 작성 | `gpt-6.1-sol` | 판단에 따른 설명·한 변수 실험·체크리스트·학생 질문 작성 |
| 기존 AI 출제 | `gpt-6.1-sol` | 레퍼런스 범위의 서술형 세트 작성, 저장 후 재사용 |
| 기존 AI 서술 평가 | `gpt-6-luna` | 기존 연습 루브릭 평가, 공식 성적·독립 풀이 난이도 근거에서 제외 |
| 수치·단위·설계 실행 | 공통 계산·EDA 엔진 | 기존 규칙 채점과 실제 실행 기록, AI가 판정을 대신하지 않음 |

공식 모델 문서: [Luna](https://developers.openai.com/api/docs/models/gpt-6-luna), [Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [Responses의 Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses). 화면의 비용은 청구액이 아니라 입력 바이트·출력 상한을 사용한 보수적 예약액이다. Luna의 기존 예약 단가를 낮추거나 캐시 할인·실패 환급을 가정하지 않는다. 준비한 최대 비용을 실행 요청의 `max_cost_usd`에도 묶어 예약액 증가를 거부한다. 두 단계 최대치 합계를 기존 공통 원장에 한 번 예약하며, 서버 내부 세션만 그 한도에서 호출할 수 있다.

## 재사용·보존·정확성 경계

- `packages/education/src/ai-policy.ts`에서 Edu 역할과 학습 목표를 정의한다. `scripts/edu-coach.mjs`는 판단과 활동을 별도로 캐시한다. 정책 버전·역할·모델·문제 버전·용도·원본 답안·퍼즐 board revision·현재 실행 요약이 키에 포함된다. 같은 조건은 0회 호출로 열 수 있다.
- 문제 원본 정답·해설은 코치 입력에서 제외한다. 기존 계산기는 현재 답안의 일치 여부만 내부 근거로 제공한다. 무료 전송 미리보기는 그 일치 여부를 공개하지 않는다. 실제 코치 활동을 받은 뒤 제출한 답안은 도움받음으로 기록하며 독립 풀이 난이도 조절에서 제외한다. 학생/QA 용도를 분리한다.
- 실행된 퍼즐 파형은 해당 board revision이 현재이고 완료된 경우에만 기존 표본의 최소·최댓값을 요약한다. 과거 결과는 상태·출처만 남기고 현재 측정값으로 전송하지 않는다. 미실행·도구 미설치·오류에서 파형을 생성하지 않는다. AI 텍스트의 의미적 정확성까지 스키마가 보장하지는 않는다.
- 응답 스키마와 근거 ID를 검증한다. 추가 점수·도구 명령·알 수 없는 근거는 거부한다. 모델은 임의 도구 실행 권한이 없다. 학습 안내 완료가 DRC/LVS/PEX·시뮬레이션 통과를 뜻하지 않는다.
- 전송 후 오류는 자동 재시도하지 않는다. Luna만 완료되면 그 판단과 원본 입력을 보존한다. 사용자가 새 활동을 명시적으로 요청할 때 완료된 단계만 재사용하고 필요한 단계만 새로 승인한다. 네트워크 응답을 못 받은 경우에는 먼저 저장 기록을 확인한다. 예약 비용은 유지한다.
- 질문·예측·학생 설명은 저장소/문제 또는 실습/버전/용도별 기기 초안으로 보관한다. 저장 실패 시 경고하고 원본을 덮어쓰지 않는다. 외부 전송 승인은 복원하지 않는다. 서버 설명은 `learner`와 `ai_draft` 작성 출처를 구분한다. MCP에는 학생 설명 자동 작성·제출 도구를 추가하지 않았다.

## 호환성과 edition 분리

기존 schema 1 학습 저장소에 선택 필드 `edu_coach_records`, `edu_coach_cache`를 추가한다. 기존 문제·답안·퍼즐·기록을 삭제하거나 재번호하지 않는다. 새 레코드는 edition, schema version, project ID, board/학습 revision, 실제 project revision, 엔진·공정 출처와 정책 버전을 보존한다. AI 결과와 학생 설명은 별도 필드다. 내보내기에 활동과 학생 설명을 포함하며 자격 증명은 포함하지 않는다.

이전 Luna 출제 세트와 단일 단계 퍼즐 답변은 기존 캐시 키로 재사용할 수 있다. 새 생성은 위 역할을 따르며 이전 결과의 모델 영수증을 재명명하지 않는다. 호환 API `study.puzzle.tutor`는 단일 단계 Sol 설명으로 유지한다. 새 UI는 `study.coach.preview/run/history/reflect`를 사용한다. 이전 1회 호출 승인을 2회 호출 승인으로 확대하지 않는다.

MCP의 Edu 표면에 읽기 전용 `register_study_coach_preview`, `register_study_coach_history`와 명시적 사용자 승인이 필요한 `register_study_coach_run`을 추가했다. Industry에는 노출하지 않는다. 공유 `requestStructured`의 기존 인자·기본 Luna 모델·공통 원장은 호환되며 Industry의 설정·데이터·업데이트 경로를 변경하지 않는다. [공통 변경 전달 정책](product-editions.md)을 따른다.

```powershell
npm run test:core

npm run typecheck
npm run build:edu
npm run build:indust
```

수동 브라우저 검증은 두 터미널에서 다음을 실행한다.

```powershell
npm run qa:study-ux -- --run=ai-roles-local --coach-fixture
npm run dev:calculators
```

`http://127.0.0.1:5177/packages/ui/qa/edu-loop/index.html`을 연다. 실제 학습 서비스와 UI를 별도 QA 저장소에 연결하며, Luna/Sol 응답만 명시적으로 표시한 고정 fixture다. 테스트용 가짜 자격 증명·별도 원장만 사용하며 외부 네트워크 생성 요청과 EDA 작업을 허용하지 않는다. 실제 사용자 키·프로젝트·인증은 변경하지 않는다.

2026-10-27에 기존 승인된 키의 무료 모델 목록 GET으로 두 모델이 목록에 있음을 확인했다. **실제 유료 생성 호출은 0회**다. 현재 사용자 학습 상한 0을 보존했다. 모델 목록 조회는 생성 성공이나 설명 품질 검증이 아니다. 새 설치 파일은 기존 합의대로 상시 라이선스 서버 연결 후 공개하며 이번에는 소스와 검증 증거만 제공한다.

로컬 핵심 회귀 373/373, edition/MCP 분리 9/9, 타입 검사와 Edu/Industry 빌드가 통과했다. 기존 대형 번들 경고는 남아 있다. 모바일 390×844에서 문서·body 너비 384 px로 가로 넘침이 없었다.
