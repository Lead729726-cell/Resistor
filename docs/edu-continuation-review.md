# Resistor Edu · 학습 이어가기와 초안 보호

2026-10-19 검토 범위는 `codex/resistor-edu`의 실제 앱과 교육 기록이다.
기존 메인 갈림길, 단일 페이지 7단계, 저장 문제·퍼즐·서명된 공용 리그,
revision에 연결된 실제 해석 기록을 재사용했다. 수식·회로·기하·엔진은 변경하지 않았다.

## 이번에 개선한 흐름

- 기본 시작 화면은 메인으로 유지한다. 기기에 남은 마지막 **화면 위치**가 있으면
  `이어서 학습`을 제공한다. 자동으로 프로젝트·실행·제출을 생성하지 않는다.
  시작 카드의 1단계 진입과 이어가기는 별도다.
- 퀴즈 내부의 문제 은행·퍼즐·리그 탭도 주소와 브라우저 이전·다음에 연결한다.
  설계에서 뒤로간 다음 메인으로 이동해도 마지막 실제 페이지를 기억한다.
- 초안을 실습 ID·프로젝트·revision·서버 저장 시각으로 확인한다. 예전 형식의
  정상 초안은 같은 프로젝트에서 읽고 새 schema로 보관한다.
- 서버 저장 시각이나 설계 revision이 달라진 초안은 자동으로 덮어쓰지 않는다.
  서버 설명과 기기 초안을 비교하고, 초안을 편집으로 가져오거나 서버 기록으로
  교체한다. 선택 전 설명 저장과 부하 적용을 막는다. 복구 자체는 회로를 바꾸지 않는다.
- 잘못된 형식·다른 edition·다른 프로젝트의 초안을 복원하지 않는다. 저장 공간
  오류를 표시하고, QA 사본 표시는 모든 실습 페이지의 제목에 유지한다.

`resistor.edu.navigation.resume.v1`은 화면 주소만 보관하며 엔진 검증 정보가 아니다.
기존 `resistor.edu.connected.lesson.v1` 기록 키와 서버 파일 형식은 유지한다.
Indust 저장 폴더·키·업데이터·네이티브 설치 파일은 변경하지 않았다.

## 실제 확인

`npm run dev:edu`로 실행한다. 이번 QA는 기존 Edu worker와 별도 `purpose=qa`
인버터 사본을 사용했다. 학생의 기존 기록은 수정하지 않았다.

- 퀴즈 문제 은행 → 퍼즐 → 브라우저 뒤로가기에서 주소와 선택 상태가 일치했다.
- 설계 5 → 6 → 뒤로가기 → 메인 → 새로고침 → 이어가기에서 5단계를 다시 열고
  적용하지 않은 95 fF 입력을 복원했다.
- 설명을 입력하고 새로고침해 초안 복원을 확인했다. 그 뒤 다른 클라이언트로 QA
  서버 설명을 저장하고 다시 열자 서버 내용과 초안을 모두 보존하고 저장을 막았다.
- 명시적 초안 복구 후 학생 설명 저장 버튼으로 확정했다. 비교·복구·페이지 이동은
  새 시뮬레이션·DRC·LVS·PEX를 실행하지 않았다. QA 사본의 설계 revision은 r2,
  실제 적용 부하는 5 fF, 해석 trial은 0개다.
- 390×844 화면에서 가로 넘침 없이 한 페이지만 표시하고 하단 다음 버튼을 확인했다.
- `tests/lesson-draft.test.ts`, `tests/edu-navigation.test.ts`는 legacy 마이그레이션,
  revision/저장 충돌, 잘못된 답안 구조와 edition·프로젝트 분리 등을 검사한다.
- 로컬 core 315건·edition/MCP 9건, typecheck, Edu·Indust 빌드,
  문서 링크와 source audit를 통과했다. 빌드의 기존 대형 chunk 경고는 남아 있다.

## 다음 우선순위

1. 엔진 연결 실패와 복구: 처음 실패한 실습 목록·문제 은행을 같은 화면에서
   다시 불러오는 흐름, 활성 실습의 다중 창 갱신과 장시간 작업 상태를 추가 검증한다.
2. 프로젝트별 학습 대시보드: 현재는 기기별 마지막 화면만 기억한다. 서버 실습별
   입력·기록·초안·실제 실행 상태를 모아 보여주고, QA 기록은 기본 목록에서 분리한다.
3. 공용 리그 가용성: 임시 터널 의존을 줄이는 지속 운영 환경과 백업·복구·상태
   점검을 준비한다. 무료 서버의 상시 가동이나 교육 효과를 확인한 것으로 표시하지 않는다.
4. 다음 native 릴리스: 이번 변경은 소스 개발판이다. 기존 공개 v0.29 설치 파일의
   포함 기능을 바꾸어 표시하지 않는다. 새 설치 파일은 OS/CPU별 설치·실행 QA 후 배포한다.
