# Resistor Edu · 재사용하는 AI 자율학습

상단 **퀴즈·자율학습** 모드에서 시작한다. **설계·시뮬레이션 학습**은 실제 회로·레이아웃 실습으로 분리되며 모드 왕복 중 입력을 유지한다. 첫 화면의 [회로 퍼즐·대화 코치](edu-circuit-puzzles.md)에서는 부품을 직접 옮기는 미션을 풀 수 있다. 기존 텍스트 문제는 **문제 은행·AI 자율학습** 탭에서 연다. 공통 계산기 예제 18개, 기존 설계 레퍼런스 서술형 40개, 검증 판단 선택형 6개와 공통 계산을 연결한 응용·심화 수치 12개를 기본 문제 은행으로 제공한다. 새 엔진이나 임의의 교육용 파형은 만들지 않는다. 계산·채점은 학습 활동이며 DRC/LVS/PEX 또는 설계 검증 결과가 아니다.

## 학생 사용 순서

1. 주제와 문제를 선택하고 조건·단위를 읽는다.
2. 수치 문제에는 `1000 ohm`, `1 kΩ`, `900 mV`, `1e-3 A` 같은 답을 입력한다. 선택 문제에는 답 하나를 고른다. 수치 허용 오차는 기준값의 0.1%이며 다른 차원·빈 입력·무한대는 거부한다. 계산식과 기준값은 기존 공통 계산기를 사용한다.
3. **채점·해설·저장 (0토큰)**을 누른다. 힌트와 해설도 저장된 내용을 사용한다. 해설을 먼저 연 뒤의 답안에는 도움받음 표시가 남는다.
4. 서술형은 기본적으로 **답안 저장·해설 비교**만 한다. 이 경우 미채점이며 가짜 점수를 만들지 않는다. AI 피드백을 원하면 이번 문제·답안의 OpenAI 전송을 명시적으로 선택한다. 점수는 원리 40, 조건·한계 35, 다음 실험 25의 연습용 평가이고 공식 교수자 성적과 별도다.
5. **다시 풀기**, **내 학습 기록**에서 이전 답안·피드백을 연다. **학습 기록 내보내기**는 문제 버전과 실제 답안을 JSON으로 보관한다. 교수자 과제 패키지의 제출 기록은 변경하지 않는다.

## 토큰 절약과 AI 새 문제

- 기본 76개 문제, 힌트, 해설, 숫자·선택 채점, 기록 재열기·내보내기는 외부 호출 0회다.
- **AI 문제 세트·비용 설정**에서 레퍼런스와 난이도를 선택한다. 같은 레퍼런스 내용·난이도·모델·출제 프롬프트 버전의 세트는 저장된 3문제를 반환한다. 저장 세트가 없을 때만 승인과 예산이 있어야 출제한다.
- 서술형 피드백도 문제 내용·버전·루브릭·모델·채점 프롬프트·정규화한 답안이 같으면 저장된 결과를 재사용한다. 새 시도는 실제 입력 원문을 별도 기록한다. 답안의 대소문자나 의미를 AI로 재작성하지 않는다.
- 재시작·페이지 새로고침도 캐시를 유지한다. 모델/문제 버전이 달라지면 이전 결과를 새 평가로 사용하지 않는다.
- AI 작성 문제는 **교수자 검토 전**, 채점은 **연습 평가**로 표시한다. 사실성·채점 품질·교육 효과는 사용자 평가 전이며 입증됐다고 주장하지 않는다.

## 연결과 비용

Node 24에서 `npm run dev:edu`로 실행한다. Edu 전용 private workspace를 사용한다. 기존 키 재사용을 사용자가 승인한 경우에만 서버에서 위치를 참조한다. 키를 Edu나 브라우저로 복사하지 않는다.

```powershell
npm run study:link -- --workspace="<Edu private workspace>" --credential-workspace="<기존 승인된 키가 있는 workspace>"
```

이 명령은 private `provider.json`을 배타 생성하므로 기존 연결을 덮어쓰지 않는다. 새 자율학습의 비용 상한은 기본 US$0이다. UI에서 사용자가 명시적으로 학습 누적 상한을 설정하고 각 새 호출을 승인해야 한다. 공통 assistant의 기존 상한·누적 예산 잠금을 함께 사용하므로 Industry의 기존 요청 비용과 분리해 초과 지출하지 않는다. 호출 전 UTF-8 바이트 기반 입력 상한과 최대 출력 4096토큰의 보수적 비용을 예약한다. 실패·중단도 예약을 유지하며 자동 재시도·환불 추정은 없다. 동일 command ID는 API를 다시 호출하지 않는다. 키 연결이 끊겨도 저장된 문제와 규칙 채점은 동작한다.

문제·답안·시도·캐시: Edu workspace의 `.runtime/education/study/state.json`. 기존 inverter 실습, 과제 브라우저 기록, Industry 프로젝트를 마이그레이션하거나 덮어쓰지 않는다. 현재 스키마는 1이며 미래 스키마를 발견하면 쓰기를 중지한다. 수동 백업은 이 디렉터리를 앱 종료 후 복사한다. 비정상 프로세스 종료로 `state.lock`이 남으면 해당 앱 프로세스가 종료됐는지 확인한 뒤 잠금 파일만 제거한다. 실제 API 오류의 상세 응답·키는 학습 기록에 보관하지 않는다.

## 엔진 및 연동 경계

공통 회로·공정·파일 엔진은 두 에디션이 공유한다. AI 요청 helper만 공통 assistant의 credential/budget을 재사용하며 학습 화면·문제·정책은 Edu 전용이다. Vite와 Electron의 `study.*` 라우터 및 Edu MCP `register_study_bank/history/generate/submit`을 제공한다. Industry에서 호출하면 저장·외부 전송 전에 거부한다. 결과에는 edition, schema_version, project_id, data_revision, 엔진 및 공정 식별 범위를 포함한다. 이 문제 은행은 실제 설계 프로젝트를 분석하지 않으므로 project_id는 null, data_revision은 0, 공정은 미지정이다. study_revision과 question_version은 별도다.

구조화 응답 구현은 [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)를 따른다. 기존 모델과 [공식 가격표](https://developers.openai.com/api/docs/pricing)의 보수적 장문 standard 요율을 유지한다. AI가 수치 답안을 판정하거나 엔진 PASS를 만들지 않는다.

## 검증

`npm run test:study`에서 계산기 기준값/단위, 오답·미채점, 저장·재열기, 세트/채점 캐시, 비용·승인, 실패 답안 보존, 동시 중복, 미래 스키마, Industry 거부를 검증한다. AI 통신 검증에는 **주입된 provider fixture**를 사용한다. 이는 실제 OpenAI 모델 실행이나 출제 품질 검증이 아니다. 이번 구현 과정에서는 유료 API를 호출하지 않았다. 실제 모델 평가, 학생 사용자 평가, 학습 효과의 사전·사후 비교는 후속 검증 대상이다.

## 난이도 분류와 자동 추천

기초 L1은 한 공식과 단위, 응용 L2는 두 계산의 연결, 심화 L3은 부하·등가회로를 포함한 다단계 계산이다. 직접 선택하거나 자동 추천을 따른다. 독립적인 동일 난이도 풀이 3개의 평균이 80점 이상이면 한 단계 올리고 40점 이하이면 한 단계 낮춘다. 문제 ID·버전당 첫 독립 결과만 사용하며 QA·해설 도움·반복 풀이·AI 서술 평가는 제외한다. 추천은 저장 문제를 고르므로 0토큰이다. 이 분류는 출제 구조와 규칙에 근거하며 학습자 대상 난이도 보정은 미실시다.

AI 새 서술형 출제는 선택 수준의 설명 요구를 프롬프트에 포함하고 기존 캐시·승인·상한 정책을 유지한다. 기존 저장 세트는 재생성하지 않는다. [통합 사용법과 실제 확인 결과](edu-learning-workflow.md)를 참고한다.


## 2026-10-26 학습 편의성 개선

- 문제 이동·필터 변경·새로고침 전후의 미제출 답안을 이 기기의 브라우저 임시 저장소에서 복원한다. Edu 학습 저장소 식별자, 학생/QA 용도, 문제 ID·버전을 모두 구분한다. 다른 기기로 동기화하는 기능은 아니다. 제출 기록과 별개이며 AI 전송 승인·점수·피드백은 임시 저장하지 않는다.
- 임시 저장소 접근·용량 오류는 화면에 표시한다. 이때 답안은 현재 화면 메모리에 유지된다. 새로고침 전에 답안을 복사하거나 명시적으로 제출해야 한다. 손상되거나 알 수 없는 형식의 기존 임시 답안은 자동 덮어쓰기하지 않는다.
- 주제·난이도·복습 필터를 바꾸면 해당 목록 안의 문제로 이동한다. 이전/다음 버튼과 문제 위치를 제공한다. 제출 때문에 현재 문제가 복습 목록에서 제외되면 피드백을 읽은 뒤 다음 문제로 이동할 수 있다.
- 기록은 선택한 학생/QA 용도와 문제 버전 기준으로 표시한다. 과거 제출을 열어도 다른 미제출 답안을 덮어쓰지 않으며, 원본 답안·피드백은 기록의 펼침 메뉴에서 읽는다. 답안을 수정하면 이전 답안의 점수는 현재 답안에서 숨긴다.
- 힌트 열기는 `study.hint`로 명시적으로 기록하며 이후 답안은 도움받음으로 분류한다. 같은 힌트를 반복해서 읽어도 중복 저장이나 AI 호출은 없다. 기존의 힌트 열람은 서버에 기록되지 않았으므로 과거 독립 풀이를 소급 재분류하지 않는다.
- 퍼즐 목록의 읽기 실패는 이전 목록·열린 보드·작성 중 설명을 유지하고 재연결할 수 있다. 목록 재연결은 새 퍼즐, 해석, 답안 제출, AI 질문을 실행하지 않는다. 처리 중 중복 조작도 막는다.

`study_store_id`는 서버의 학습 저장소 위치에서 계산한 불투명 식별자로 도구 응답·context에 추가했다. 기존 스키마 1의 서버 학습 기록은 그대로 읽으며 답안·프로젝트를 이관하지 않는다. 임시 저장을 지원하려면 프런트엔드와 학습 서비스를 함께 업데이트한다. 구버전 서비스에 이 식별자가 없으면 화면에서 업데이트가 필요함을 표시한다.

검증 범위와 실행 결과는 [학습 UX 개발 루프 기록](edu-ux-loop-20261026.md)에 기록한다. 사용자 학습 효과 평가는 별도이며 아직 수행하지 않았다.
