# Resistor Indust · 세 회로를 열고 신호를 확인하기

이 가이드는 [측정 보고서](report.json)에 연결된 프로젝트를 편집하고 다시 해석하는 절차입니다. 조작 설명은 현재 UI 소스 기준이며, 이번 환경에서 GUI 브라우저 재현은 수행하지 못했습니다. 수치 결과는 실제 native API 실행으로 검증했습니다.

## 1. 한 회로만 가져오기

프로젝트 열기 화면의 **설계 파일 가져오기**에서 [TIA](sensor_current_tia.register.zip), [Track/Hold](adc_track_hold.register.zip), [히스테리시스 비교기](sensor_schmitt.register.zip) 중 하나를 고릅니다. ZIP을 풀어 회로 파일만 넣지 말고 ZIP 자체를 가져옵니다. 새 프로젝트에 회로도와 계층, 테스트벤치 설정이 만들어집니다. 저장된 과거 실행은 상속하지 않으므로 처음에는 미실행 상태가 맞습니다.

## 2. 회로도에서 신호 경로 읽기

**회로도 / Schematic** 작업 화면에서 최상위 포트를 확인한 뒤 필요한 하위 셀로 들어갑니다. 공통 전원은 `VPWR`, 접지는 `VGND`, 내부 기준은 `VCM`, 바이어스는 `BIAS`입니다. 회로도 계층의 전선은 전기적 연결이며 물리적인 금속 배선이 아닙니다.

| 프로젝트 | 먼저 볼 노드 | 하위 셀에서 볼 것 |
| --- | --- | --- |
| TIA | `IIN`, `OUT`, `VCM` | `PRACTICAL_TIA`의 RF·CF와 `SOC_OTA` 입력 연결 |
| Track/Hold | `VIN`, `CLK`, `HOLD`, `OUT` | `PRACTICAL_SAMPLE_SWITCH`의 상보 게이트·10 pF 저장 C·1 GΩ 누설 경로 |
| 비교기 | `VIN`, `SUM`, `OUT`, `VCM` | `PRACTICAL_HYSTERESIS`의 100 kΩ/1 MΩ, `SOC_COMPARATOR`의 `PREAMP`와 출력 인버터 |

## 3. 실행 조건을 한 번에 하나씩 정하기

다음 실행에서 **검사 종류 → 시뮬레이션**을 선택하고 조건 단계로 진행합니다. 처음에는 `TT`, `1.8 V`, `27 °C`, 출력 부하 `100 fF`를 사용합니다. 먼저 OP로 바이어스를 확인하고 다음에 TRAN을 실행하면 원인을 나누어 볼 수 있습니다. TIA만 AC를 추가로 지원합니다.

TRAN 기본값은 총 `320 µs`, 시간 간격 `50 ns`입니다. 지정 측정창이 전체 들어오도록 기간은 적어도 320 µs, 시간 간격은 100 ns 이하로 설정합니다. 공급 전압 허용 범위는 1.6–1.8 V입니다. 대화창에서 앞뒤 단계로 이동하거나 미리보기만 보는 것은 해석 실행이 아닙니다. 최종 실행 동작 후 실제 엔진 상태와 로그를 확인하세요.

## 4. 결과에서 전압과 전류 연결하기

**시뮬레이션 / Simulation** 화면에서 이번 실행을 선택합니다. 실행 완료 여부와 지정 회로 기준의 통과 여부를 따로 확인하고 프로젝트 revision도 비교합니다. 회로를 수정한 뒤에는 예전 결과가 최신 설계를 검증하지 않습니다.

TIA는 `input_current`가 증가할 때 `OUT−VCM`이 내려가는지 봅니다. 양의 입력 전류는 `IIN`으로 들어오는 방향입니다. 기본 전류 자극은 50.1–150 µs에서 1 µA, 150.1–250 µs에서 0.5 µA, 이후 0이며 목표 변환량은 각각 약 −0.2 V, −0.1 V입니다. 이 값은 RF로 계산한 기대값이고 실제 수치는 파형과 보고서에서 확인합니다. AC의 입력 1 A는 선형 이득 정규화용이며 실제 1 A를 회로에 흘린 TRAN 시험이 아닙니다.

Track/Hold는 `CLK`가 HIGH인 동안 추적하고 LOW가 되면 `HOLD`에 값을 저장합니다. 30 µs부터 40 µs 동안 HIGH이며 주기는 100 µs입니다. 85 µs와 185 µs에 입력이 변할 때 이전 값이 유지되는지 `VIN`, `HOLD`, `OUT`을 겹쳐 봅니다. 획득 오차는 각 주기의 60–68 µs, 홀드 오차와 드루프는 90–118 µs 구간에서 측정합니다. `HOLD`의 69.99→70.05 µs 변화는 전하 주입과 클록 피드스루가 합쳐진 순간 변화이며 각각을 분리한 측정은 아닙니다.

비교기는 `VIN` 상승 구간 40–140 µs, 하강 구간 180–280 µs를 봅니다. 입력이 상승할 때와 하강할 때 서로 다른 전압에서 출력이 바뀌는지 확인합니다. 보고서 임계값은 `OUT`이 VDD/2를 지나는 시각의 입력 값입니다. 각 단조 램프에서 한 번만 전환했는지를 검사했으며, 무작위 잡음 자극에 대한 면역 시험을 한 것은 아닙니다.

`supply_current`는 `−i(VDD)`입니다. 양의 값은 VDD가 회로에 공급하는 전류를 뜻합니다. 이 신호의 평균 전력에는 이상 입력·클록 구동기의 에너지가 들어 있지 않습니다. TIA AC는 복소수 전류 흐름 시각화 지원 대상이 아니므로 OP/TRAN의 실제 전류 결과를 사용하세요.

## 5. 변경하고 이전 결과와 비교하기

새 프로젝트에서 부품 하나 또는 실행 조건 하나씩 변경합니다. TIA의 RF를 바꾸면 예상 전류-전압 이득이 바뀌고, CF 변경은 전체 OTA 동특성과 함께 확인해야 합니다. Track/Hold의 저장 C 변경은 획득 시간·드루프·스위칭 오차에 함께 영향을 줍니다. 비교기의 `RIN/RFB` 변경은 임계값 폭에 영향을 주며 템플릿 매개변수의 허용 비율은 0.05–0.2입니다. 이런 관계는 설계 방향을 설명하는 것이며 변경 후 기준 통과를 보장하지 않습니다.

회로도에서 부품 값을 직접 편집해도 생성 당시 템플릿의 판정 목표까지 자동으로 바뀌지는 않습니다. 예를 들어 RF를 바꾼 뒤 원래 이득 목표를 통과하지 않는 것은 회로 해석 실패와 다릅니다. 새 목표가 필요하면 템플릿 매개변수로 새 프로젝트를 생성하고, 기존 목표를 유지할 때는 바뀐 회로의 실제 값과 원래 기준을 비교하세요.

외부 출력 부하 변경을 먼저 시험하려면 Track/Hold의 `load_F`를 `2e-12` F, 즉 2 pF로 설정하고 TRAN을 다시 실행하세요. 이 조건의 실제 실행 결과는 보고서의 `supplemental_runs`에 있습니다. 단순히 화면 설정을 바꾼 것과 변경값이 적용된 실행 결과를 구분하고, 실패했다면 로그와 해당 테스트벤치의 `CLOAD` 값을 확인합니다.
