# Operator-owned native backends

The backend infrastructure is implemented. No Cadence, Synopsys or Siemens licensed executable is installed in the verified environment. All seventeen commercial catalogue entries and release-specific recipe candidates therefore remain **unverified**. The real ngspice local/HTTP calibration is explicitly open source and proves the transport, receipt, artifact and signed-number pipeline only.

## API

`backend.catalog` returns `{tools,profiles}`. `backend.list_profiles` returns safe metadata only. Local operator `backend.register {manifest}` stores an immutable version ID. `backend.validate {profile_id}` returns `{valid,profile,checks,fingerprint,checked_at}`. Availability means a regular executable and bounded resources exist, or the authenticated companion reports these facts; it never proves a license checkout or foundry signoff. Shared users cannot register profiles.

`backend.configure {project_id,settings,expected_revision?,command_id?}` saves a new immutable revision with `backend_setup` and `active_backend:'commercial'`; the existing open-source setup is preserved. Settings are `{profile_id,profile_hash?,operation,top_cell,parameters?,netlist_text?}`. The selected top must be a real KLayout cell. External OA/NDM library cells are operator recipe inputs, not silently substituted for the native project. `analysis.configure` switches active mode back to open source. Raw layout import clears both electrical setups.

`backend.run` accepts project ID, optional operation and receipt/revision preconditions. It returns an asynchronous Run with `workflow:'commercial-backend'`, backend profile ID and actual input/resource hashes. Operations are simulation, drc, lvs, pex, layout_export, netlist_export and implementation. A bare GDS never acquires an invented reference circuit: recipes that consume an electrical reference require explicit data-only SPICE text. Client scripts/includes/external file sources are rejected. Registered trusted site scripts may implement native netlisting/export independently.

`backend.read_artifact {run_id,key}` returns bounded actual declared results (`summary,waves,currents,rc,exchange,netlist,stdout`), never site resources, token files or arbitrary paths. `backend.import_layout {project_id,run_id,key:'exchange',top_cell?,expected_revision?,command_id?}` explicitly imports a current, same-project actual GDS/OAS result in a new revision. The original snapshot remains available. Binary layouts bypass text parsers and are decoded with KLayout; this proves interchange readability, not physical signoff.

## Operator manifests

See `adapters/commercial/calibration-ngspice.manifest.json` for a functioning local example. Local runner fields are `kind:'local',executable,env_names,resources,recipes`. Resources map names to approved absolute files or small opaque directory trees. Each recipe contains argv (excluding the executable), declared relative output names, timeout_s 1..3600, optional primitive parameter schemas, optional requires_netlist and operator result_context. String parameters require enumerated safe tokens; numbers need finite bounds. The subprocess uses argv and `shell=False`; scripts/argv/executable paths are never project inputs.

Placeholders are `{input.gds}`, `{input.oas}`, `{input.project}`, `{input.settings}`, `{input.netlist}`, `{input.bindings_tcl}`, `{input.bindings_il}`, `{input.site_tcl}`, `{input.site_il}`, `{input.calibre_svrf}`, `{output_dir}`, `{top_cell}`, `{resource.NAME}` and `{parameter.NAME}`. Generated Tcl/SKILL bindings serialize fixed data only. Site-entry wrappers load an explicitly registered `site_script`. Calibre input SVRF supplies actual GDS/reference paths and includes registered `deck`; foundry/release-specific deck behavior still requires operator validation. All referenced script/model dependencies must be included in an explicit resource directory or declared files; undeclared host dependencies are outside the certified hash footprint.

Resource copies are immutable job inputs and private. Opaque directories are copied/hashed without proprietary decoding: aggregate resources <=256 MiB and <=4096 entries per tree, regular files only, no symlinks. Larger libraries require a smaller versioned site export snapshot; they are explicitly unavailable under these bounds. Inputs are <=32 MiB aggregate, each declared output <=16 MiB, logs <=4 MiB. Overlong/truncated logs receive explicit incomplete markers and cannot certify PASS. Exact executable/resource copies and opaque outputs containing configured private environment values cannot be exported as results. Environment **names** are configured; values are inherited privately and redacted before log persistence.

## Licensed-host companion

`platform/commercial/agent.py` is standard-library Python 3 on Linux/Windows. The operator config file is `{allowed_roots:[absolute paths],profiles:[local manifests]}`. Start it with `python agent.py --profiles operator-profiles.json --state private-state --token-file private-state/agent.token`. The token is generated privately (0600 on Linux, restricted ACL on Windows). Do not paste it into a manifest, API, UI or command line. The default bind is loopback; remote deployment requires an operator HTTPS reverse proxy with certificate verification. Worker agent manifests are `{runner:{kind:'agent',url,token_file,profile_id},...}`. HTTP is allowed only on loopback or `host.docker.internal` for the same-PC Docker companion; redirects are forbidden.

The companion has authenticated `/rpc` methods profile.list/validate/check_settings and job.submit/status/cancel/artifact. Registration remains an operator-installed file operation. Two subprocess slots and a sixteen-job queue are bounded. SQLite receipts bind command IDs to exact immutable input packages; retries replay the same native identity. Cancellation stops native process groups/Windows process trees. Restart marks interrupted jobs failed/unknown and uses recorded process creation identities to stop surviving owned processes without targeting reused PIDs. No job is automatically replayed. Agent-local profile resources are copied on that licensed host and are never transferred to the worker.

Local freshness recomputes stat-cached hashes; remote reads use the latest explicitly validated fingerprint/checked_at without network under the native global lock. New remote jobs revalidate before/after execution. A remote resource mutation becomes stale after validate/new-job refresh; offline reads do not claim live remote filesystem monitoring.

## Result scope and evidence

Only recognized complete result evidence can be PASS. Exit zero alone, a version string, license errors, incomplete logs, unknown grammar, PSF/PSFXL/FSDB/TR0 binary data and encrypted vendor databases do not become fabricated success. Supported narrow text parsers are documented by `commercial_results.py` and `tests/commercial/test_adapters.py`. Operator exporters must produce supported text or normalized register-commercial-results v1. Licensed-run recipe compatibility is still pending actual installed releases and site decks.

Every commercial current flow has `geometry_linkage:'unverified'`, no inferred physical path and canonical input_origin. Real signed values from a recipe or external native database do not prove correspondence with the original GDS snapshot, even when a GDS argument was passed. User path declarations retain this unverified correspondence status.

Reproduce: `node tests/integration/commercial-backend.mjs` starts isolated native/companion services inside the existing Docker image, retains source-state logs, and writes `.runtime/evidence/commercial-backend.json`. Genuine ngspice resistor OP returns1 V, source current -1 mA and resistor current +1 mA. Separate actual GDS copy calibration proves byte transfer/read/import, explicitly not a proprietary vendor export. Original failed test attempts are retained. The release report copies the sanitized case summary into docs/evidence.
