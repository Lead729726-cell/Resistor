# Linux EDA worker

The worker runs real KLayout, ngspice, Magic and OpenCircuitDesign Netgen from the pinned `hpretl/iic-osic-tools` image. It uses Python stdlib HTTP and SQLite, with KLayout OASIS snapshots as the geometry authority. The Windows launch script publishes port 8765 inside the container exclusively through host `127.0.0.1:18765`; the other existing service on host 8765 is preserved. `MOS_TOKEN` is supplied by the launcher and is never written to project artifacts or analysis manifests.

Start from the repository root with `node scripts/worker.mjs start`; stop with the corresponding `stop` command. Browser/desktop clients use the parent project's transport. Direct Linux launch requires `MOS_TOKEN`, `MOS_WORKSPACE`, `MOS_STATE` and the installed tools/PDK. `/health` only exposes service and protocol; all RPC operations require `X-MOS-Token`.

## Runtime decision

The existing, already downloaded image contains the required public profile and avoids rebuilding five EDA engines or downloading another PDK. This is a reproducibility and compatibility decision, not a switch in the selected process. The Dockerfile pins digest `sha256:92961478ad3c4f508efb42d9ccdba12ab262eb42a14926d2bd49862230ba8521`, image release 2025.12. Its Ciel installation supplies SKY130A at open_pdks commit `d400e26845538beaeb7cc5fdb9bfc06c30ea27cb`. The actual `.config/nodeinfo.json` is preserved in each provenance record. Tools verified in this image: ngspice 45.2, Magic 8.3.582, Netgen 1.5.313 and KLayout 0.30.5. The installed Xschem now supplies a tested headless netlisting bridge for generated flat native cells; interactive external launch and arbitrary imported .sch execution remain outside this worker.

## Public examples

* `inverter`: the public `sky130_fd_sc_hd__inv_1` geometry plus actual public `sky130_fd_sc_hd__tapvpwrvgnd_1` cells abutted on both sides. A standalone inv_1 has no body taps and correctly fails the public full DRC deck. Adding actual tap cells and tying bodies to the rails gives the validated four-port inverter (`A VGND VPWR Y`). The explicit native schematic uses NMOS W/L 0.65/0.15um and HVT PMOS 1.0/0.15um. Its layout template is fixed; editing the schematic changes simulation and makes LVS report any disagreement.
* `mosfet`: the installed public Magic `sky130_fd_pr__nfet_01v8` generator with its guard ring, W=0.65um, L=0.15um, nf=m=1. `viagate=0` selects the generator's documented local-interconnect gate contact option: default minimum gate metal1 landing pads in this installed generator fail the full `met1.6` minimum-area rule. This does not remove the gate contact; it avoids a noncompliant metal1 overlay. Source/drain use the public defaults. W/L regeneration follows the same generator and is blocked when manual geometry edits would be overwritten.
* `wire`: actual 200um by 1um metal1 with two explicit GDS pin-purpose polygons and endpoint labels. Magic extracts its distributed resistance and ground capacitance. The post-layout testbench explicitly grounds native `VSUBS`, loads OUT with 100fF and 1Mohm, and drives IN with the same 1.8V pulse. The raw extracted netlist is preserved.
* `current_mirror` and `differential_pair`: two- and three-NFET physical cores generated from the same public PCell, with actual contacts, vias and metal3 fanout rails. Native full DRC, LVS, PEX and pre/post DC tests are described below and their exported geometry is included in `examples/sky130`.
* `fixture`: marked illustrative geometry for geometry/UI operation without a PDK. Physical analyses are unsupported.

GDS text alone does not preserve Magic port declarations. MOS and wire generation adds the actual SKY130 pin-purpose polygons beneath the port labels, just as the public standard-cell GDS does. It does not replace extracted connectivity. Testbenches instantiate the actual extracted `.subckt` port order, rather than assuming the schematic declaration order survives extraction.

## Analysis provenance and limits

Each job snapshots the input revision before execution, saves arguments, settings, logs, return codes, original extraction outputs, netlists and raw waveforms, and hashes all installed primitive/model SPICE files, technology/setup/generator files and relevant executable binaries. Hash caching invalidates on size, mtime or ctime changes. Result freshness checks both revision and this dependency fingerprint. Display colors and illustrative heights are absent from native analysis inputs.

ngspice uses unchanged public TT/FF/SS model files for the verified NMOS/HVT PMOS pair, the public mismatch parameter files with switches off, and a verbatim public `all.spice` parameter preamble. Loading the entire library parses many unrelated models and was measured at roughly a minute per tiny circuit; the tested subset completes in under a second in this environment for the default small examples. Generated subset includes and original source hashes are saved with each run. MOS widths are micrometers, and only the verified single-finger/single-instance mapping (`nf=1, m=1`) is enabled. Other mappings return typed unsupported errors. OP exposes actual voltage/current samples and nested BSIM gm/gds/Vth/Vdsat; operating-region estimates are explicitly inferred from those values and applied biases. MOS DC defaults to Vgs 0..1.8V at Vds=1.8V, Vbs=0V and also supports Id-Vds sweeps at a supplied Vgs. Inverter DC sweeps input. Persisted testbench settings select analysis, corner, temperature (-40..125C), supply (0.1..1.8V), MOS biases, load, transient duration and step; per-run settings override them. The defaults remain TT, 27C and 1.8V. Transients permit at most 1ms and 200000 nominal points; large traces may hit the 120-second native-engine timeout and are failed with unknown results. Native geometric schematics and hierarchical blocks support actual netlist authoring. Arbitrary external testbench scripts and statistical Monte Carlo remain unsupported.

DRC runs the installed public Magic `drc(full)` deck, parses actual rule descriptions/rectangles and crosschecks the native count. A normally completed job with violations is `completed + fail`; engine/parser failures are `failed + unknown`. Public deck pass is not foundry signoff. Netgen compares actual Magic connectivity extraction with the explicit native schematic using the installed SKY130 setup. Reports and JSON are retained; there is no automatic mismatch repair. Both property and pin failures are classified.

PEX uses Magic's separate R/C path: `extract`, `ext2sim labels on`, `ext2sim`, `extresist tolerance 0.001`, `extresist all`, then `ext2spice extresist on`, zero capacitance/resistance output thresholds and no MOS merging. Magic 8.3.582 predates the simplified resistance extraction sequence introduced in 8.3.597; the prior-version SIM/NODE preparation is required. This is not `ext2spice lvs`. Native R/C counts and values are preserved even when zero. No field solver, RF/substrate signoff, cap cross sections or exact RC heatmap is claimed. Native `.ext/.nodes/.res.ext` remain available for future spatial mapping.

Physical stack depths and thicknesses are unknown/null. Layer colors come from the installed PDK LYP, while all displayed heights are explicitly illustrative. Rendering a mask is not a process reconstruction or TCAD simulation.

## Geometry and editing

Coordinates are decimal strings, validated against signed int32 bounds and the 5nm manufacturing grid for the 1nm baseline DBU. Explicit route widths keep both edges on grid. KLayout owns geometry and stable shape/instance properties; scene occurrence IDs include hierarchy instance paths. Hierarchy transforms and holes travel to scene data. Generated PCell child shapes are read-only; explicitly created user cells are editable through cell-targeted commands. Commands save a new immutable OASIS/project snapshot and SQLite history. Undo/redo restores metadata and geometry under a new monotonic revision; divergent edits clear redo. On worker restart interrupted jobs become `failed + unknown`, with retained failure logs, and interrupted experiments are marked failed.

GDS/OASIS export verifies canonical polygon/hole topology, physical DBU and hierarchy signatures after actual file reload; stable ID preservation is measured. App metadata is in a hash-matched `.mos.json` sidecar. Import is restricted to the workspace and does not execute third-party code. Imported cell/port names outside the supported engine identifier subset can be viewed but cannot enter executable scripts. Only the locally installed trusted PDK scripts execute. No RPC method accepts arbitrary commands or shell input.

## Register extension verification

`extensions.mjs` verifies optimistic revisions, persistent command receipts, monotonic undo/redo, polygon holes, paths, labels, pins, editable user cells, rotation/mirror/copy/arrays, cycle and overflow rejection, and immutable SHA-checked project bundles. `native-extended.mjs` verifies exact geometric pin/wire connectivity, explicit junction crossing behavior, hierarchical native blocks through real ngspice and Netgen, TT/FF/SS DC/AC/OP, and persisted testbench settings. `optimizer.mjs` verifies genuine grid/random/TPE evaluation with mandatory DRC/LVS gates, feasible ranking, constraint failure, cancellation, Xschem-generated SPICE simulation, and actual extracted R/C table counts.

`analog.mjs` verifies the two physical analog cores, public via helpers, MOS output curves and native BSIM operating-point values. The current mirror uses two identical public NFET cores and metal3 REF/OUT/VGND rails. The differential-pair core uses three NFETs, a BIAS terminal, two current-output drain terminals, and a physically routed internal tail node. These are transistor cores with explicit testbenches, not a complete operational amplifier. Both passed real Magic full DRC and Netgen LVS; actual PEX includes 146R/3C and 212R/21C respectively. Public via1/via2 helpers supply cut/enclosure geometry. The isolated via2 PCell adds a 0.5um square metal3 landing pad because the unchanged deck requires met3.6 minimum area of 0.24um2; routed analog rails already satisfy that area.

`faults.mjs` applies a gate short, open drain and incorrect bulk net to the fixed inverter's native reference. Actual Netgen reports each mismatch, then reports a unique match after each explicit repair. `bundle-history.py` rechecksums changed OASIS payloads and verifies that restoring an existing immutable revision rejects both stable-ID rebinding and changed electrical net annotations. `budgets.mjs` verifies wall-time range bounds, persistent create/evaluate receipts, the two-experiment concurrency gate and cancellation. `deadline.mjs` uses two genuine long post-layout differential-pair transients to keep the native pool busy and verifies that a 60-second experiment deadline cancels its queued DRC, leaves the objective score null and preserves a manifest with no launched engine commands.

`interruption.py` launches a separate worker process against isolated SQLite/OASIS state on an internal container-only port. It interrupts two actual long native engines and a queued candidate gate, then reopens that worker state. All three native jobs become failed/unknown; the experiment and interrupted trial become failed with a null score and no active run IDs. Completed trial artifacts remain available. This regression leaves the primary UI worker running.

Xschem interchange emits native `.sch` devices using installed public symbols and electrical labels, then invokes the actual headless Xschem netlister. Simulation may consume that generated SPICE. The Xschem bridge currently accepts flat native cells; native hierarchical SPICE netlisting and verification are separately tested. No imported Xschem file or arbitrary Tcl/command property executes through RPC.

MOS OP quantities gm/gds/Vth/Vdsat come from the actual nested BSIM device. `region_estimate` is an explicitly labeled inference from those quantities and applied biases. DC curve derivatives are finite differences of actual sampled currents. `dc_sweep:vds` with `vgs_V` produces actual Id–Vds data. Testbench controls remain within the explicit 1.8V, -40..125C app bounds, using public TT/FF/SS model files unchanged.

Experiments isolate every candidate in its own immutable native project. The optimizer supports one or two W/L variables on the verified single-MOS PCell, 1..16 trials, deterministic seeds, at most two running experiments, and an aggregate 60..1800s wall budget including native queue waits. Every feasible score requires actual PCell generation, DRC pass, LVS pass and ngspice DC completion. Failed gates or constraints assign no score. TPE uses local seeded univariate Parzen densities after three feasible startup trials. `area_um2` means actual bounding-box footprint. `power_W` is applied Vds times maximum sampled drain current, a peak DC drain-power measurement; it is not total operating-point or dynamic system power. Worker interruption keeps artifacts and marks experiments failed; canceled/expired jobs cannot publish pass results. Unknown results and canceled trials remain visible rather than becoming feasible scores.

Project bundles contain exactly project.json, layout.oas, pdk-lock.json and manifest.json, with checksums and exact geometry validation. `new` assigns a local ID; `replace` creates a new revision; `restore` preserves approved authority IDs/revisions while requiring a precondition for existing state and rejecting immutable ID-to-geometry conflicts or rewind. Persistent receipts bind command IDs to exact request payloads and are committed in the same SQLite transaction as edits or job submission. Cloud authorization is handled by the parent application, not by a permissive native worker endpoint.

Large layouts stay hierarchical. `view.get_scene max_shapes/bounds` returns exact scoped geometry and an authoritative hierarchy-counted total. Actual 100000-tile source geometry returned 2000 shapes in 292ms in a local HTTP measurement; the viewer's separate browser benchmark reports rendering scope and hardware. Full 100000-shape JSON remains available for exchange/tests but is about 37.7MB. Extracted R/C inspection reports actual electrical node IDs and SI values; exact spatial element-to-polygon mapping remains unknown and no synthetic heatmap is supplied.

Remaining native limits are arbitrary MOS nf/m mappings, generalized analog routing, arbitrary executable PDK scripts/unsupported model families, general Xschem hierarchy/file import, full RC spatial correspondence, foundry signoff and physically sourced process reconstruction/TCAD. The local PDK registry now supports confined compatible static technology/model resources and explicit imported-GDS analysis as described in PDK_SETUP.md. Existing SKY130 deck/model/license provenance remains pinned; illustration heights are never represented as process thicknesses.

## Signed current and native thread budget

`current_flow.py` instruments a copy of the native netlist with actual zero-volt series sources and reads ngspice signed terminal currents. MOS D→S is a reference direction for the drain terminal, including transient displacement current; it does not imply that gate/body terminal currents vanish. Extracted symmetric D/S correspondence requires proof from the actual resistor connectivity before the logical drain's sense source is selected. Testbench voltage-source currents use the native positive-to-negative reference without negation. Negative values reverse that reference. Verified generated single-MOS D/S contact labels supply the only physical paths; arbitrary imports, inverter devices and testbench sources remain spatially unmapped. Imported metadata cannot assert those generated-layout anchors. Extracted distributed R/C currents remain omitted, and complex AC results explicitly have no scalar current direction.

`test_current_flow.py` verifies 16 actual-engine MOS/inverter OP/DC/transient pre/post cases, original waveform compatibility, resistor/current-source signs and AC unsupported status. `test_current_flow_api.py` verifies four main-worker API cases, including probe-name collisions and imported-layout mapping guards. Every original native log and immutable input remains retained under `.runtime/evidence` or `.runtime/eda/runs`.

The pinned ngspice image's `/foss/tools/ngspice/share/ngspice/scripts/spinit` sets eight OpenMP model-evaluation threads. Two allowed native jobs can therefore oversubscribe a desktop CPU. An edited inverter W=1.3um transient originally completed in 96.157s under desktop load, despite no convergence failure. Controlled sequential reference/probe replays took about 0.2s; two concurrent default-thread probes took 9.891s and 15.644s. The same two decks with one thread took 0.167s and 0.218s. Generated control sections now explicitly set `num_threads=1`, and run manifests record that resource setting. Models, electrical solver tolerances, timesteps and completion bounds are unchanged. `test_thread_budget.py` exercises two genuine concurrent edited-inverter jobs and compares their voltages and signed currents with an eight-thread reference; the saved values were identical. See the ngspice manual's “Ngspice on multi-core processors using OpenMP” section for this control setting: https://ngspice.sourceforge.io/docs/ngspice-manual.pdf.

## Registered PDK / imported layout setup

`pdk_registry.py` and `configured_analysis.py` add a separate local registry and explicit imported-layout port-bias workflow without changing the fixed-profile globals. Profile/resource and geometry hashes pin each configured job. The latest isolated `test_pdk_setup.py` run passed 32 cases, including twelve actual completed Magic/Netgen/ngspice jobs, a separately canceled job, uploaded include/lib models and custom static technology, mutation staleness, immutable receipt replay and actual multi-top scene/simulation binding. Earlier failed attempts and their native logs remain available. The original 16 signed-current/voltage compatibility regressions also passed after integration. Independent validator/current calibration audits are maintained separately by the audit agent. Refer to PDK_SETUP.md for API, security constraints and explicit unsupported mappings.
