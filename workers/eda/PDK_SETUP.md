# Local PDK registry and imported-layout analysis

This extension leaves the original verified SKY130 adapter and snapshots intact. It registers separate immutable profile IDs and creates explicit configured-analysis revisions. A validation pass means confined resources and supported input syntax, not foundry qualification or engine compatibility certification. Actual jobs retain native logs and can fail or report unknown.

## Registry API

`pdk.list_profiles {}` returns profiles with `id`, `name`, `version`, `manifest`, `fingerprint`, `built_in`, `available`, `capabilities`, and `checks`. Additional fields include `source`, `validation`, `lock.signature/files` and the original registered fingerprint. The built-in ID is `sky130A`; its original public TT/FF/SS subset remains unchanged.

`pdk.register {manifest, package_base64?}` accepts schema_version 1, id/name/version, root, magic_rc, magic_tech, netgen_setup, model_file, model_mode (`lib`, `include`, or reserved built-in `sky130-subset`), corners, spice_scale and optional KLayout layer_file. Empty optional resource fields are omitted. An installed root must stay under `/foss/pdks` or the managed PDK directory. Installed Ciel aliases may resolve within `/foss/pdks`; managed symlinks are forbidden. An uploaded ZIP is limited to 16 MiB compressed, 96 MiB expanded, 4096 entries and 16 MiB per entry. Uploaded root is relative to its newly allocated managed package. IDs cannot be overwritten; replaying the exact same manifest/package returns its existing profile.

ZIP traversal, absolute/drive paths, case collisions, special files, symlinks and native interpolation/quote characters are rejected. Model and palette files stay within the declared root. Explicit installed native decks may be referenced from `/foss/pdks`. Model dependencies are recursively checked after joining SPICE continuation lines. Only classic SPICE model families/data are supported. `.control`, executable directives, external-process XSPICE, dynamic-code loaders and external-file model features are forbidden.

Static Magic technology data and confined `.tech` include fragments are supported. Tcl interpolation/executable commands are rejected; `$SUB`, `$VDD` and `$GND` refer only to the generated fixed bindings. Uploaded Magic RC/Netgen Tcl must match a trusted installed deck and executes from that installed canonical path, never beside uploaded sibling scripts. Arbitrary uploaded executable Tcl, plugins, user shell commands, commercial PDK licenses and installation credentials are outside this API. Resource hashes and declared version are retained. Backup must explicitly include managed PDK resources to restore uploaded profiles; project bundles contain locks rather than redistributing model/deck files.

`pdk.validate {profile_id? | manifest?}` returns `valid`, checks, fingerprint, and an optional profile. The no-argument form validates the existing installed SKY130 profile. File changes recompute the fingerprint and invalidate configured runs. A plain include declares exactly one corner; multiple corners require actual `.lib` sections present in model_file rather than metadata-only corner labels.

## Imported-GDS workflow

`layout.import` preserves every actual cell and accepts an optional actual top_cell. Multiple top cells require explicit selection. An import clears prior analysis_setup; without a matching app sidecar it also clears inherited schematic/testbench electrical metadata. Original immutable revisions remain available through history.

`analysis.inspect {project_id, profile_id, top_cell?}` reads actual KLayout roots/labels and invokes Magic connectivity extraction with a 60-second native timeout. It returns top_cells, selected top_cell, labels, declared ports in their actual extraction order, checks, revision, fingerprint, inspection_id/artifacts and the last 64 KiB of actual log_text. Labels without native port declarations are not guessed into circuit ports. At most two inspections run simultaneously. Inspection never edits original geometry.

`analysis.configure {project_id, settings, expected_revision?, command_id?}` stores profile_id/profile_hash, top_cell, corner, temperature_C, ports, analysis, pex and optional reference_spice. Port rows contain name, mode (`ground`, `voltage`, `floating`) and dc_V. Every actual extracted port must occur exactly once; an explicit zero-volt ground is required. Referenced global nodes require an explicit port bias or proven resistor connection, rather than an invented ground tie. Ports accept identifiers with an optional `!` suffix; other syntax returns a typed unsupported error. Temperature is bounded -100..300C and biases -100..100V; these are application bounds, not a assertion that a PDK device tolerates them.

Analysis is op, dc or tran. DC adds sweep_port/start_V/end_V/step_V; the swept port must be voltage-biased and the step must advance to the endpoint within 200000 nominal points. Transient adds duration_s/step_s, bounded to 1ms, >=1ps steps and 200000 nominal points. This schema has constant explicit DC port biases, so transient verifies the resulting circuit response; arbitrary PULSE/PWL/testbench scripts are unsupported. AC complex currents are not emitted as scalar directions.

Inspection/configuration preparation occurs outside the global job/SQLite lock. Commit rechecks the observed revision and profile fingerprint, updates the authoritative selected project cell and saves the exact new OASIS hash. A completed command receipt is returned before any repeat inspection, including after later file changes.

`analysis.run {project_id, expected_revision?, command_id?}` returns an asynchronous Run with kind simulation and workflow configured-layout. It uses actual Magic connectivity/PEX extraction and ngspice with explicit biases, temperature/corner/scale and the actual execution subcircuit port order. Port order may vary between connectivity and resistance extraction; exact port names and the explicit bias map remain authoritative. No old schematic or example testbench is reused. Generic include/lib models execute genuine model resources; generic model dependencies are copied into the run folder. Each ngspice job explicitly uses one model-evaluation thread, preserving existing desktop concurrency behavior.

`analysis.verify {project_id, kind:'drc'|'lvs'|'pex', expected_revision?, command_id?}` uses the configured native resources. The directly declared DRC full variant is preferred, otherwise the first directly declared static style is used; include-only style declarations require an adapter. Technology name/load checks and selected style are recorded, so failure cannot silently continue against Magic's prior technology. LVS requires explicit bounded reference_spice with matching top/ports. Reference text permits netlist data only; control, includes and external process/code/file directives are rejected. Native failures are failed/unknown; actual violations/mismatches are completed/fail. Existing job.status/logs/cancel and persistent receipts apply. Changed geometry or resources require reconfiguration; stored results become stale. Model/deck/resource hashes and settings are in the native manifest and profile-lock.json.

## Signed-current scope and verification

Actual zero-volt probes measure native M MOS, verified public SKY130 wrapper terminals, eligible R/C/source branches and the explicit port-bias voltage sources. Native polarity is preserved. Extraction may exchange symmetric MOS drain/source terminals; an imported layout has no schematic proof for relabeling them. Imported device/bias currents therefore remain spatially unmapped. No numerical current is inferred from a voltage, and no fabricated vector path or conductor streamline is attached. Other custom subcircuit/device mappings and distributed PEX R/C current paths remain unsupported and are reported as partial coverage.

Run `node tests/integration/pdk-setup.mjs`. It runs an isolated native worker and exercises actual naked SKY130 MOS OP/DC/transient, pre/post PEX simulation, full DRC, LVS, extraction, uploaded classic model/custom static technology/include/lib, resource staleness and negative input cases. The uploaded tiny model is an explicitly declared classic level-1 approximation used for a compatibility regression, never a replacement claimed to reproduce foundry BSIM physics. All inputs/logs are retained under `.runtime/evidence/pdk-setup-*/state`; summary is `.runtime/evidence/pdk-setup.json`. Independent parser/current audits live in `.runtime/evidence/pdk-setup-audit.json`.
